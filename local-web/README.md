# Aruba 2930F 로컬 웹 1.3.6

## 실행

Windows 11 x64에서 배포 ZIP의 **모두 압축 풀기**를 선택하고 **Start-Local-Web.cmd**를 더블클릭하세요. 기본 브라우저에서 로컬 관리 화면이 열립니다. Python과 SSH 라이브러리를 배포본에 포함했습니다. 장비에 접속할 때에는 이 PC에서 해당 스위치까지 SSH 통신이 가능해야 합니다.

기본 주소는 http://127.0.0.1:18765/ 입니다. 포트가 사용 중이면 다른 로컬 포트를 선택해 브라우저를 엽니다. 실행 파일을 다시 열면 기존 서버의 창으로 접속합니다. 새 버전으로 교체할 때는 작업이 끝난 뒤 기존 화면에서 **서버 종료**를 누르고, 새 ZIP을 별도 폴더에 풀어 실행하세요. 브라우저 탭을 닫아도 수집은 계속됩니다. 사이드바의 **서버 종료**를 누르면 실행 중인 로컬 서버와 SSH 계정 세션을 종료합니다.

## 관제와 장비 관리

기존 Windows EXE와의 기능별 대조 및 이번에 추가한 항목은 [기능 비교표](FEATURES_KO.md)에 정리했습니다.

* **AP 로그 관제**에서 스위치 이벤트 로그를 파일로 열거나 붙여넣습니다. **스위치에서 로그 가져오기**는 SSH로 수집한 실제 로그를 같은 화면에 표시합니다. 처음 열면 로그 미선택 상태입니다. 파일, 붙여넣기 또는 SSH 수집으로 받은 로그에서만 포트 상태를 표시합니다. 관제의 세 가지 색은 전력 미공급, 전력 공급 중 링크 끊김, 전력 공급 중 링크 연결 관측을 뜻합니다. 링크 관측은 AP 전용 포트에서 스위치가 기록한 유선 링크 상태입니다. PoE와 링크의 판단 근거가 부족한 포트 수는 화면에 따로 안내합니다.
* **SSH 접속 설정**에서 장비 사용자 이름과 암호를 적용합니다. 조회·로그 수집·백업·포트 제어 시 처음 보는 장비는 해당 IP와 SSH 포트에서 받은 호스트 키 지문을 자동으로 저장하고 작업을 이어갑니다. 이후 지문이 달라지면 인증 전에 연결을 차단합니다. 장비 교체로 키가 변경된 경우 새 지문을 장비에서 확인한 뒤 **SSH 접속 설정**에서 기존 등록을 삭제하고 다시 접속하세요.
* **포트 관제·제어**에서 **실시간 조회**를 선택하고 조회 대상에 스위치 주소와 포트를 입력한 다음 **포트 조회**를 누르세요. SSH 계정이 없으면 같은 화면에서 입력합니다. 계정을 적용하면 해당 대상의 조회가 이어지며, 이미 계정이 있으면 곧바로 조회합니다. **관제·비교**에서는 기존 Windows 프로그램이 저장한 CSV를 열 수 있습니다. 매트릭스는 실측 0 W를 빨간색으로, 전력이 공급되지만 정상 공급이나 LLDP의 AP 이름을 확인하지 못한 포트를 노란색으로, 정상 공급과 LLDP의 AP 이름을 함께 확인한 포트를 초록색으로 표시합니다. 실측 전력값이 없는 포트는 색을 비워 둡니다. 실시간 링크 Up·Down은 `show interfaces status`에서 해당 포트의 Status 열을 읽습니다. 포트 관리 설정과 실제 링크는 상세에서 각각 확인할 수 있습니다. 기존 CSV를 열면 그 파일을 저장한 시점의 링크가 표시됩니다. **우선 확인**은 점검 목록을 엽니다. 두 CSV 또는 실시간 조회와 과거 CSV를 비교해 포트별 이전·이후 값을 볼 수 있습니다. 과거 기록에서 장비를 조치하려면 먼저 그 포트를 실시간 조회합니다. 대상 목록은 JSON 프로필로 저장하고 다시 불러올 수 있습니다.
* **포트 제어**에서 단일 포트를 직접 지정하거나 조회한 포트를 선택합니다. PoE 켜기·끄기와 포트 Up·Down을 각각 실행합니다. 대상과 명령을 검토하고 화면의 확인 문자열을 입력합니다. 일괄 작업은 최대 10개 단위로 다음 실행을 확인합니다. PoE ON 직후 응답이 끊기거나 첫 조회에 이전 설정이 나오면 같은 장비·포트의 PoE 사용 설정을 읽기 전용으로 다시 확인합니다. 상태가 확인되면 다음 포트로 진행합니다. 확인이 끝내 실패하면 결과에서 처음 확인하지 못한 포트와 이후 명령을 보내지 않은 포트를 볼 수 있습니다.
* **구성 백업**에는 스위치 IPv4 주소 또는 <code>IPv4:SSH포트</code>를 한 줄에 하나씩 입력합니다. 모델과 호스트 키를 확인한 장비에서 실행 설정을 읽습니다. 파일 이름 방식, 동시 접속 수, 최대 시도 횟수를 지정할 수 있습니다. 결과에서 장비별 TXT, Excel 보고서와 작업 로그를 내려받습니다.
* **작업 이력**에서 이 웹 서버로 만든 결과 파일과 저장된 백업·포트 제어 기록을 확인합니다.

**대상 목록 편집**에서는 스위치별 행을 관리하고 Excel 표를 미리 본 뒤 기존 목록에 추가하거나 교체합니다. 적용한 포트는 바로 매트릭스에 나타납니다. **빠른 PoE 제어**는 선택 전체를 사전 검토한 뒤 승인된 대상을 처리합니다. 일반 일괄 제어에서는 10개 단위로 계속 여부를 결정합니다. **화면 요소 식별**을 열면 입력한 값 없이 화면 요소의 고정 식별자로 수정 요청을 작성할 수 있습니다.

## 저장 위치

구성 백업에서 **폴더 선택**으로 위치를 고르거나 경로를 입력하면 해당 위치에도 날짜·실행 시각별로 결과가 저장됩니다. Windows 공유 폴더를 직접 지정한 경우에는 그 위치에 설정 파일도 복사되므로 공유 권한을 확인하세요. **결과 폴더 열기**를 누르면 Windows 탐색기에서 확인할 수 있습니다.

웹 버전의 데이터 폴더는 현재 Windows 사용자의 <code>%LOCALAPPDATA%\Aruba2930FLocalWeb\data</code>입니다. <code>outputs</code> 아래에 실행별 설정과 보고서가 저장됩니다. SSH 계정과 암호는 서버 메모리에만 보관합니다. 설정 백업 TXT에는 스위치가 출력한 설정값이 포함됩니다.

## 배포 구성

Windows 프로그램 v0.10.1의 Aruba 2930F 수집·제어 코어를 사용합니다. 배포본은 웹 화면, 로컬 HTTP 서버, Windows x64용 CPython 3.14.3 및 고정된 의존성을 포함합니다. 서버는 루프백 주소에서만 요청을 받습니다. GitHub 계정이나 인터넷 연결 없이 실행할 수 있습니다.
