# Aruba 2930F 로컬 웹 1.8.0

## 실행

Windows 11 x64에서 배포 ZIP의 **모두 압축 풀기**를 선택하고 **Start-Local-Web.cmd**를 더블클릭하세요. 기본 브라우저에서 로컬 관리 화면이 열립니다. Python과 SSH 라이브러리를 배포본에 포함했습니다. 장비에 접속할 때에는 이 PC에서 해당 스위치까지 SSH 통신이 가능해야 합니다.

기본 주소는 http://127.0.0.1:18765/ 입니다. 포트가 사용 중이면 다른 로컬 포트를 선택해 브라우저를 엽니다. 실행 파일을 다시 열면 기존 서버의 창으로 접속합니다. 새 버전으로 교체할 때는 작업이 끝난 뒤 기존 화면에서 **서버 종료**를 누르고, 새 ZIP을 별도 폴더에 풀어 실행하세요. 이 웹 앱을 연 마지막 탭이나 브라우저 창을 닫으면 약 5초 뒤 로컬 서버와 SSH 계정 세션이 종료됩니다. 이 앱의 다른 탭이 열려 있거나 새로고침하는 동안에는 계속 사용할 수 있습니다. 백업·조회·포트 제어가 실행 중이면 해당 작업을 마친 뒤 종료됩니다. 다시 사용할 때는 **Start-Local-Web.cmd**를 여세요. 즉시 종료할 때는 사이드바의 **서버 종료**를 사용할 수 있습니다.

상단의 테마 버튼은 누르면 적용될 모드를 표시합니다. 다크 모드에서는 **☀ 라이트**, 라이트 모드에서는 **☾ 다크**를 누르세요. 로컬 웹과 단독 HTML 모두 같은 방식으로 전환합니다.

## 다른 기기에서 HTTPS 접속

1. 서버 PC에서 **네트워크 공유**를 열고, 다른 기기가 접속할 유선 또는 Wi-Fi 주소를 선택한 뒤 스위치를 **ON**으로 바꾸세요. 프로그램을 시작할 때 기본값은 **OFF**입니다.
2. 다른 PC나 휴대폰 브라우저의 주소창에 화면에 표시된 `서버IP:18766`을 입력하세요. 주소를 직접 입력하거나 표시된 HTTPS 주소를 복사해 사용할 수 있습니다. HTTP로 열린 경우에도 같은 주소의 HTTPS 화면으로 이동합니다.
3. 브라우저에서 인증서 경고가 나타나면 서버 PC의 네트워크 공유 화면에 표시된 SHA-256 지문과 접속 기기의 인증서 지문을 대조하세요. 서버 주소에 연결할 수 있는 기기는 호스트의 SSH 세션을 사용해 포트를 조회하고 제어할 수 있습니다. 원격 기기가 접속할 때까지 서버 PC의 탭을 열어 두세요.
4. 서버 PC에서 스위치를 **OFF**로 바꾸면 접속 중인 원격 브라우저의 연결이 끊어지고, 다시 켤 때까지 새 연결도 닫힙니다. 같은 서버 주소를 다시 선택하면 이전에 입력한 주소로 재접속할 수 있습니다.

방화벽 때문에 시간이 초과되면 **네트워크 공유**를 켠 후 서버 PC에서 배포 폴더를 관리자 PowerShell로 열고 <code>.\Enable-LAN-Firewall.ps1</code>을 실행하세요. 이 규칙은 모든 원격 IPv4 대역을 허용하며, 선택한 서버 주소와 네트워크 어댑터에서 이 앱의 TCP 18766에 적용됩니다. v1.5.0의 규칙을 사용하던 PC에서도 새 배포 폴더의 스크립트를 다시 실행하면 허용 범위가 갱신됩니다. <code>.\Enable-LAN-Firewall.ps1 -Remove</code>로 제거할 수 있습니다.

## 관제와 장비 관리

기존 Windows EXE와의 기능별 대조 및 이번에 추가한 항목은 [기능 비교표](FEATURES_KO.md)에 정리했습니다.

* **AP 로그 관제**에서 스위치 이벤트 로그를 파일로 열거나 붙여넣습니다. **스위치에서 로그 가져오기**는 SSH로 수집한 실제 로그를 같은 화면에 표시합니다. 처음 열면 로그 미선택 상태입니다. 파일, 붙여넣기 또는 SSH 수집으로 받은 로그에서만 포트 상태를 표시합니다. 관제의 세 가지 색은 전력 미공급, 전력 공급 중 링크 끊김, 전력 공급 중 링크 연결 관측을 뜻합니다. 링크 관측은 AP 전용 포트에서 스위치가 기록한 유선 링크 상태입니다. PoE와 링크의 판단 근거가 부족한 포트 수는 화면에 따로 안내합니다.
* 포트 조회·제어, 스위치 로그 수집 또는 구성 백업을 처음 실행하면 **SSH 접속 계정** 입력 창이 열립니다. 사용자 이름과 비밀번호를 적용하면 선택한 작업이 이어지고, 같은 세션의 다음 작업에도 이 계정을 사용합니다. 계정을 바꾸거나 해제할 때, 또는 저장된 장비 지문을 관리할 때는 현재 로컬 웹 주소에서 `#` 이후 부분을 `#connect`로 바꾸세요. 주소에 `#`가 없으면 끝에 `#connect`를 붙이세요. 첫 접속에서 장비 지문을 자동 등록하며, 같은 IP와 SSH 포트에서 지문이 바뀌면 인증 전에 연결을 차단합니다. 장비 교체가 원인인 경우에는 새 지문을 장비에서 확인한 뒤 기존 등록을 삭제하고 다시 접속하세요.
* **관제·제어**에서 스위치 주소와 포트를 입력하고 **포트 조회**를 누르세요. **관제**에는 실시간 조회 결과가, **우선 확인**에는 점검할 포트가 표시됩니다. 실측 0 W는 빨간색, 전력이 공급되지만 정상 공급과 LLDP의 AP 이름을 함께 확인하지 못한 포트는 노란색, 두 조건을 모두 확인한 포트는 초록색입니다. 실측값이 없는 포트는 무색으로 표시합니다. 링크 Up·Down은 `show interfaces status`에서 읽습니다. 조회 대상 목록은 JSON 프로필로 저장하고 다시 열 수 있습니다.
* **변화만 보기**를 켜면 같은 스위치 주소·SSH 포트·인터페이스의 직전 관측과 현재 관측에서 달라진 포트를 찾을 수 있습니다. 첫 조회는 비교 기준이 됩니다. 한 포트만 재조회하면 다른 포트의 직전 관측은 유지됩니다. **우선 확인**에서는 전력 미공급 또는 공급 점검 포트를 선택해 매트릭스에서 위치를 확인하고 조치할 수 있습니다.
* **포트 상태 매트릭스**에서 실시간 조회한 포트 타일을 누르면 해당 스위치 주소와 포트가 제어 대상으로 표시됩니다. 여러 포트를 제어하려면 **여러 포트 선택**을 켜고 대상 타일을 누르세요. 조회 결과 목록의 체크박스로도 같은 대상을 선택할 수 있습니다. 대상 표시를 확인하고 **PoE ON**이나 **PoE OFF**를 누르면 실행합니다. 조회 전에는 매트릭스의 **제어 옵션**에서 스위치 주소와 포트 번호를 직접 지정할 수 있습니다. PoE 켜기·끄기와 포트 활성화·비활성화 중 원하는 작업을 고릅니다. **제어 대상과 명령 검토**를 사용하는 일반 제어에서는 확인 문구를 입력합니다. 일반 일괄 제어는 최대 10개 단위로 다음 실행을 확인합니다. PoE ON 직후 응답이 끊기거나 첫 조회에 이전 설정이 나오면 같은 장비·포트의 PoE 사용 설정을 읽기 전용으로 다시 확인합니다. 상태가 확인되면 다음 포트로 진행합니다. 확인이 끝내 실패하면 결과에서 처음 확인하지 못한 포트와 이후 명령을 보내지 않은 포트를 볼 수 있습니다.
* **PoE OFF**는 스위치가 PoE 사용 설정을 확인한 포트에서 실행할 수 있습니다. 물리 링크가 Down이거나 LLDP에 AP 이름·모델이 없을 때도 선택한 포트의 전원을 끌 수 있습니다. **포트 비활성화**를 일괄 실행하려면 링크 Up과 LLDP에서 확인한 AP-535가 필요합니다.
* **PoE ON·OFF 후 전력 확인**은 빠른 제어와 일반 제어에서 자동으로 진행됩니다. 결과에서 변경 전 전력과 재조회한 전력(W)을 비교하세요. 두 시점 모두 실측값이 있을 때 차이를 표시합니다. 재조회 시점에 AP가 부팅 중이면 이후 소비 전력은 달라질 수 있습니다.
* **구성 백업**에는 스위치 IPv4 주소 또는 <code>IPv4:SSH포트</code>를 한 줄에 하나씩 입력합니다. 모델과 호스트 키를 확인한 장비에서 실행 설정을 읽습니다. 파일 이름 방식, 동시 접속 수, 최대 시도 횟수를 지정할 수 있습니다. 결과에서 장비별 TXT, Excel 보고서와 작업 로그를 내려받습니다.
* 작업 중에는 상단에 현재 단계를 표시합니다. 처리 수가 확인된 단계에는 완료 건수·전체 건수와 진행률이 나타나고, 전체 수를 알 수 없는 단계에는 대기 표시가 나타납니다.

**대상 목록 관리**를 펼치면 스위치별 행을 편집하거나 Excel에서 복사한 표를 미리 보고 기존 목록에 추가하거나 교체할 수 있습니다. 검증해 적용한 포트는 **관제**의 매트릭스에 나타납니다. 빠른 PoE 제어 결과에는 실행한 포트와 이미 요청한 상태여서 건너뛴 포트가 표시됩니다. **화면 요소 식별**을 열면 입력한 값 없이 화면 요소의 고정 식별자로 수정 요청을 작성할 수 있습니다.

## 저장 위치

구성 백업에서 **폴더 선택**으로 위치를 고르거나 경로를 입력하면 해당 위치에도 날짜·실행 시각별로 결과가 저장됩니다. Windows 공유 폴더를 직접 지정한 경우에는 그 위치에 설정 파일도 복사되므로 공유 권한을 확인하세요. **결과 폴더 열기**를 누르면 Windows 탐색기에서 확인할 수 있습니다.

웹 버전의 데이터 폴더는 현재 Windows 사용자의 <code>%LOCALAPPDATA%\Aruba2930FLocalWeb\data</code>입니다. <code>outputs</code> 아래에 실행별 설정과 보고서가 저장됩니다. SSH 계정과 암호는 서버 메모리에만 보관합니다. 설정 백업 TXT에는 스위치가 출력한 설정값이 포함됩니다.

## 배포 구성

Windows 프로그램 v0.10.1의 Aruba 2930F 수집·제어 코어를 사용합니다. 배포본은 웹 화면, 로컬 HTTP 서버, Windows x64용 CPython 3.14.3 및 고정된 의존성을 포함합니다. 기본 접속 주소는 이 PC의 루프백입니다. 네트워크 공유를 켜면 선택한 네트워크 주소에서도 HTTPS 연결을 받습니다. GitHub 계정이나 인터넷 연결 없이 실행할 수 있습니다.
