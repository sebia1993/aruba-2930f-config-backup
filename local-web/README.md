# Aruba 2930F 로컬 웹 1.30.4

지원 장비는 Aruba 2930F와 **Aruba 2930M-24G-PoE+ (JL320A)**입니다. 장비에 SSH로 로그인하면 로컬 웹이 스위치 모델을 확인합니다. HPE에서 2930M의 `WC.17.02.0006`은 Boot ROM 버전으로 안내합니다. 실행 중인 ArubaOS-Switch 소프트웨어 버전은 장비의 `show version` 출력에서 별도로 확인할 수 있습니다. [HPE 2930M/F 버전 안내](https://arubanetworking.hpe.com/techdocs/AOS-Switch-RN/Content/16.10RN/WC/Upgrade%20information.htm)

JL320A의 기본 포트는 독립형에서 `1`처럼 번호로 입력합니다. 스택에서는 로컬 웹이 모든 멤버의 모델을 자동으로 확인합니다. 모든 멤버가 JL320A로 확인되면 `1/1`, `2/1`처럼 멤버 번호와 포트 번호를 함께 입력할 수 있습니다.

## 실행

Windows 11 x64에서 배포 ZIP의 **모두 압축 풀기**를 선택하고 **Start-Local-Web.cmd**를 더블클릭하세요. 기본 브라우저에서 로컬 관리 화면이 열립니다. Python과 SSH 라이브러리를 배포본에 포함했습니다. 장비에 접속할 때에는 이 PC에서 해당 스위치까지 SSH 통신이 가능해야 합니다.

기본 주소는 http://127.0.0.1:18765/ 입니다. 포트가 사용 중이면 다른 로컬 포트를 선택해 브라우저를 엽니다. 실행 파일을 다시 열면 기존 서버의 창으로 접속합니다. 새 버전으로 교체할 때는 작업이 끝난 뒤 기존 화면에서 **서버 종료**를 누르고, 새 ZIP을 별도 폴더에 풀어 실행하세요. 이 웹 앱을 연 마지막 탭이나 브라우저 창을 닫으면 약 5초 뒤 로컬 서버와 SSH 계정 세션이 종료됩니다. 이 앱의 다른 탭이 열려 있거나 새로고침하는 동안에는 계속 사용할 수 있습니다. 백업·조회·포트 제어가 실행 중이면 해당 작업을 마친 뒤 종료됩니다. 다시 사용할 때는 **Start-Local-Web.cmd**를 여세요. 즉시 종료할 때는 사이드바의 **서버 종료**를 사용할 수 있습니다.

상단의 테마 버튼은 누르면 적용될 모드를 표시합니다. 다크 모드에서는 **☀ 라이트**, 라이트 모드에서는 **☾ 다크**를 누르세요.

## 다른 기기에서 HTTPS 접속

1. 서버 PC에서 **네트워크 공유**를 열고, 다른 기기가 접속할 유선 또는 Wi-Fi 주소를 선택한 뒤 스위치를 **ON**으로 바꾸세요. 프로그램을 시작할 때 기본값은 **OFF**입니다.
2. 다른 PC나 휴대폰 브라우저의 주소창에 화면에 표시된 `서버IP:18766`을 입력하세요. 주소를 직접 입력하거나 표시된 HTTPS 주소를 복사해 사용할 수 있습니다. HTTP로 열린 경우에도 같은 주소의 HTTPS 화면으로 이동합니다.
3. 브라우저에서 인증서 경고가 나타나면 서버 PC의 네트워크 공유 화면에 표시된 SHA-256 지문과 접속 기기의 인증서 지문을 대조하세요. 서버 주소에 연결할 수 있는 기기는 호스트의 SSH 세션을 사용해 포트를 조회하고 제어할 수 있습니다. 원격 기기가 접속할 때까지 서버 PC의 탭을 열어 두세요.
4. 서버 PC에서 스위치를 **OFF**로 바꾸면 접속 중인 원격 브라우저의 연결이 끊어지고, 다시 켤 때까지 새 연결도 닫힙니다. 같은 서버 주소를 다시 선택하면 이전에 입력한 주소로 재접속할 수 있습니다.

방화벽 때문에 시간이 초과되면 **네트워크 공유**를 켠 후 서버 PC에서 배포 폴더를 관리자 PowerShell로 열고 <code>.\Enable-LAN-Firewall.ps1</code>을 실행하세요. 이 규칙은 모든 원격 IPv4 대역을 허용하며, 선택한 서버 주소와 네트워크 어댑터에서 이 앱의 TCP 18766에 적용됩니다. v1.5.0의 규칙을 사용하던 PC에서도 새 배포 폴더의 스크립트를 다시 실행하면 허용 범위가 갱신됩니다. <code>.\Enable-LAN-Firewall.ps1 -Remove</code>로 제거할 수 있습니다.

## 관제와 장비 관리

**포트·PoE 관리**에서 스위치 IP를 한 줄에 하나씩 입력하고 **모니터링 시작**을 누르면 전체 대상을 즉시 조회합니다. 간격은 1~60분이며 기본값은 1분입니다. IP만 입력한 스위치는 매 주기마다 현재 물리 포트 목록을 다시 읽으므로 포트 추가와 제거가 반영됩니다. IP 뒤에 포트 목록이나 범위를 지정한 스위치는 지정한 포트만 모니터링합니다. 매트릭스와 목록에서 필터를 바꾸거나 일부 포트를 선택해도 전체 대상을 계속 조회합니다. 종료하려면 **■ 중지**를 누르세요. 설정한 주기에 앞선 작업이 진행 중이면 그 회차를 건너뛰고, 누적된 **건너뛴 조회 N회**를 모니터링 상태에 표시합니다. 앱 탭을 열어 둔 동안 서버가 주기를 관리하고, 마지막 탭을 닫으면 모니터링도 종료됩니다. 전력값이 누락되면 마지막 측정값과 시각을 ‘갱신 지연’으로 구분합니다. 스위치가 SSH 계정을 거부하면 자동 조회를 일시 중지합니다.

자동 조회 도중에도 포트를 선택해 **Power OFF**, **Power ON** 또는 **케이블 진단**을 예약할 수 있습니다. 서버는 현재 조회를 끝내고 예약한 순서대로 작업합니다. 다음 자동 조회는 예약이 끝난 뒤 예정된 회차부터 이어집니다. 예약 목록에서 대상 스위치와 포트, 실행 상태를 확인하거나 대기 중인 작업을 취소할 수 있습니다. 같은 포트에 반대 전력 동작을 예약하려면 앞선 예약을 취소한 다음 원하는 동작을 다시 선택하세요. 예약 시 확정한 대상은 화면에서 선택을 바꿔도 유지됩니다. 예약한 전력 작업은 실행 직전에 해당 포트만 다시 조회하고, 이미 요청한 상태이면 변경을 건너뜁니다. 예약은 최대 24건까지 접수하며, 접수 후 10분 동안 시작되지 못한 예약은 실행하지 않고 자동 취소합니다. 계속 필요한 작업은 최신 포트 상태를 확인한 후 새로 신청하세요. 서버를 다시 시작하면 이전 예약은 실행되지 않습니다.

접수 응답이 끊기면 기존 요청 ID로 최대 5번 접수 상태만 다시 확인합니다. 제어 명령은 자동 재전송하지 않습니다. 접수를 확인하지 못한 경우 같은 탭의 추가 수동 요청을 막고 **접수 상태 다시 확인**과 **미접수 요청 종료**를 표시합니다. 후자는 서버가 기록을 찾으면 기존 작업의 상태를 반환하며, 기록이 없으면 해당 ID를 영구 종료하여 늦게 도착한 기존 요청도 실행되지 않게 합니다. 같은 탭을 새로고침할 때는 브라우저가 저장한 요청 ID로 접수를 다시 확인합니다(브라우저 저장소를 사용할 수 있는 경우). 최근 결과 목록에서 사라진 작업도 SQLite 작업 이력으로 접수 여부와 요약 상태를 확인할 수 있습니다. 데이터 폴더의 `receipt-diagnostics.jsonl`에는 요청 ID, 발생 시각, HTTP 상태 및 단계 코드만 기록하며, 계정·대상 주소·CLI 출력은 저장하지 않습니다. 이 진단 파일은 약 1MB에 도달하면 한 번 순환 보관합니다.

작업 완료 후 전력·케이블 결과를 화면에 반영하지 못한 경우에는 실행 결과를 **결과 미확인**으로 표시하고, 같은 포트의 후속 예약은 자동 취소합니다. 모니터링은 실행 슬롯을 해제하고 다음 주기를 계속하며, 오류 포트는 수동 재조회 후 새 작업을 신청하세요. 변경 명령은 자동으로 다시 보내지 않습니다.

매트릭스나 결과 목록에서 포트 상세의 **전력 추이**를 펼치세요. 최근 1시간·24시간·7일 중 하나를 고르면 측정 시각별 실측 전력(W)을 볼 수 있습니다. 점을 누르면 해당 측정 시각과 전력, 직전 실측 대비 증감이 표시됩니다. 첫 실측은 점 하나로, 0 W는 0선 위의 점으로 표시합니다. 연속해서 관측한 모니터링 구간은 선으로 잇고, 수동 조회는 점으로 표시합니다. 측정 실패나 중단 구간에는 전력값을 채우지 않습니다. 이 버전에서 조회한 이력은 서버 PC에 최근 7일간 보관하며 서버를 다시 열어도 같은 포트에서 확인할 수 있습니다.

기존 Windows EXE와의 기능별 대조 및 이번에 추가한 항목은 [기능 비교표](FEATURES_KO.md)에 정리했습니다. 자동 조회·예약 충돌 및 구형 SSH 의존성 검증 범위는 [안정화 점검 기록](../docs/LOCAL_WEB_STABILITY_REVIEW_20261123_KO.md)에 정리했습니다.

* 포트 조회·제어, 케이블 진단 또는 스위치 컨피그 백업을 처음 실행하면 **SSH 접속 계정** 입력 창이 열립니다. 사용자 이름과 비밀번호를 적용하면 선택한 작업이 이어지고, 같은 세션의 다음 작업에도 이 계정을 사용합니다. 계정을 바꾸거나 해제할 때, 또는 저장된 장비 지문을 관리할 때는 현재 로컬 웹 주소에서 `#` 이후 부분을 `#connect`로 바꾸세요. 주소에 `#`가 없으면 끝에 `#connect`를 붙이세요. 첫 접속에서 장비 지문을 자동 등록하며, 같은 IP와 SSH 포트에서 지문이 바뀌면 인증 전에 연결을 차단합니다. 장비 교체가 원인인 경우에는 새 지문을 장비에서 확인한 뒤 기존 등록을 삭제하고 다시 접속하세요.
* **포트·PoE 관리**에서 스위치 IP를 한 줄에 하나씩 입력하고 **포트 조회**를 누르세요. IP만 입력하면 스위치의 `show interfaces status`에서 확인된 물리 포트를 조회합니다. 링크가 Down인 포트와 PoE를 지원하지 않는 포트도 포함됩니다. 특정 포트만 보려면 IP 뒤에 공백을 넣고 포트 목록이나 범위(`1,3,5-8`)를 입력하세요. 여러 스위치에서 두 방식을 섞어 사용할 수 있습니다. 한 스위치의 목록을 읽지 못하면 해당 주소에 **포트 목록 조회 실패**가 표시되고 다른 스위치에서 읽은 포트는 계속 볼 수 있습니다. 조회가 시작되면 **포트 상태 매트릭스**가 맨 위에 표시됩니다. 포트는 스위치 주소별로 모아 포트 번호순으로 표시합니다. **조회 설정**에서 스위치 주소·포트와 모니터링 간격을 변경할 수 있습니다. 전체 조회가 실패하면 입력란이 다시 열리므로 입력한 내용을 수정한 뒤 조회하세요. 일부만 실패하면 매트릭스의 **조회 실패** 개수를 눌러 현재 조회 범위에서 실패한 포트만 보세요. 개수를 다시 누르면 이전 화면으로 돌아갑니다. 실패가 모두 해소된 뒤에도 **조회 실패 0개**를 눌러 돌아갈 수 있습니다. 실패 표시가 있는 포트를 누르세요. 상세에서 실패 이유를 확인하고 **이 포트만 재조회**를 누르면 해당 스위치의 그 포트만 갱신합니다. 실패한 포트를 한꺼번에 갱신하려면 **실패 포트만 재조회**를 누르세요. 정상 포트의 기존 결과도 계속 볼 수 있습니다. **결과 목록**으로 전환하면 스위치별로 포트 번호, 전력 판정, 실측 W, LLDP 이름을 볼 수 있습니다. 두 보기에서 선택한 포트와 필터를 공유합니다. **전체 재조회**는 IP만 입력한 스위치의 물리 포트 목록을 새로 읽고, 포트를 지정한 스위치는 입력 범위를 다시 조회합니다. **선택 N포트 재조회**는 체크한 포트만 갱신하며 필터로 가려진 선택도 포함합니다. 체크한 포트가 없으면 현재 상세에서 보고 있는 포트 한 개를 갱신합니다. 한 대만 점검하려면 스위치 필터에서 장비를 고르고 원하는 포트를 선택하세요. 링크 상태와 관측 시각은 포트를 선택해 상세에서 확인하세요. 매트릭스에서 전력 상태별 개수를 누르면 해당 상태의 포트가 보입니다. 여러 상태를 고르면 선택한 상태가 모두 표시됩니다. 같은 개수를 다시 눌러 해제할 수 있고, 마지막 상태까지 해제하면 모든 전력 상태가 표시됩니다. 휴대폰에서는 **검색·필터**를 한 번 펼쳐 검색어와 필터를 변경할 수 있습니다. 실측 0 W는 빨간색, 전력이 공급되지만 정상 공급과 LLDP의 AP 이름을 함께 확인하지 못한 포트는 노란색, 두 조건을 모두 확인한 포트는 초록색입니다. 실측값이 없는 포트는 무색으로 표시합니다. 링크 Up·Down은 `show interfaces status`에서 읽습니다. 조회 대상 목록은 JSON 프로필로 저장하고 다시 열 수 있습니다.
* **결과 목록**에서 **전체 포트**와 **변화 포트 N개**를 전환하세요. 변화 개수는 현재 검색·스위치·전력 필터에 해당하는 포트 중에서 셉니다. 변화 목록은 같은 스위치 주소·SSH 포트·인터페이스의 직전 측정과 비교해 달라진 셀에 **직전값 → 현재값**을 표시합니다. 첫 조회는 **비교 전**으로 표시됩니다. 비교한 결과가 같으면 **변화 포트 0개**로 표시됩니다. 한 포트만 재조회하면 다른 포트의 비교 결과는 유지됩니다. 매트릭스로 돌아가면 공통 필터에 맞는 포트가 모두 보이고 변한 타일에는 점선이 표시됩니다.
* **포트 상태 매트릭스**의 타일은 포트 번호, LLDP 이름, 링크 상태를 같은 위치에 표시합니다. LLDP 이름이 비어 있어도 한 줄을 비워 타일 높이를 맞춥니다. 기본 크기에서는 공간이 충분한 PC에 한 줄 12개, 휴대폰에 한 줄 4개가 보입니다. 매트릭스 위의 **블록 크기** 슬라이더로 모든 타일의 크기를 함께 조절할 수 있습니다. 크기를 바꿔도 선택한 포트와 전력 상태 필터가 유지됩니다. 타일 바탕색은 PoE 전력 상태를, 테두리와 타일 아래쪽 문자는 `show interfaces status`로 확인한 물리 링크를 나타냅니다. 초록 테두리의 **↑ Up**은 링크 연결, 빨간 테두리의 **↓ Down**은 링크 끊김, 회색 테두리의 **—**는 현재 링크값 미조회를 뜻합니다. 0 W에서도 링크가 Up이면 빨간 바탕에 초록 테두리가 표시됩니다. 긴 LLDP 이름은 가운데를 생략해 끝 식별자를 보여줍니다. PC에서 타일에 마우스를 올리거나 PC·휴대폰에서 타일을 눌러 포트 상세를 열면 전체 이름을 볼 수 있습니다. 이웃이 한 대이고 AP 모델이나 장비 유형, 활성 무선 AP 역할이 확인되면 AP 이름으로 표시합니다. 이름만 있으면 포트 상세에 **LLDP 이웃 이름 · AP 유형 미확인**이 표시됩니다. 이웃이 여러 대면 타일에 **이웃 N대**가 표시됩니다. 포트 상세에서 스위치가 보고한 각 이름을 확인하세요. 제어할 포트의 타일을 차례로 누르면 선택한 스위치 주소와 포트가 표시됩니다. 선택한 타일을 다시 누르면 해당 포트만 빠집니다. 조회 실패 표시가 있는 타일은 실패 사유와 재조회 버튼을 엽니다. **전체 선택**을 누르면 현재 범위의 선택 가능한 포트가 모두 선택되고, 같은 버튼이 **전체 선택 해제**로 바뀝니다. 기본 범위는 검색·필터 결과 전체이며 다른 페이지도 포함합니다. 필터나 목록 페이지를 바꿔도 선택이 유지됩니다. 제어 영역의 **화면 밖** 개수는 선택한 포트 중 현재 결과에 보이지 않는 수입니다. 이 포트도 선택한 제어 대상에 포함됩니다. **제어 옵션**에서 현재 스위치 또는 등록된 전체로 범위를 변경할 수 있습니다. 조회 결과 목록의 체크박스로도 같은 대상을 선택할 수 있습니다. 포트를 선택하면 전력 상태 필터의 **전력 미측정** 옆에 **Power OFF**와 **Power ON**이 나타납니다. 아래쪽 포트를 선택해도 화면 상단에서 전원 버튼을 누를 수 있습니다. **Power OFF**는 선택한 포트의 PoE 공급을 차단하고 **Power ON**은 공급을 켭니다. 두 버튼 모두 즉시 실행되며, 마지막 선택을 해제하면 숨겨집니다. 조회 전에는 매트릭스의 **제어 옵션**에서 스위치 주소와 포트 번호를 직접 지정할 수 있습니다. PoE 켜기·끄기와 포트 활성화·비활성화 중 원하는 작업을 고릅니다. **제어 대상과 명령 검토**를 사용하는 일반 제어에서는 확인 문구를 입력합니다. 일괄 포트 비활성화는 처음에 전체 대상을 한 번 확인하면 선택한 포트를 차례로 처리합니다. 다른 일반 일괄 작업은 최대 10개 단위로 다음 실행을 확인합니다. 전력 공급을 켠 직후 응답이 끊기거나 첫 조회에 이전 설정이 나오면 같은 장비·포트의 PoE 사용 설정을 읽기 전용으로 다시 확인합니다. 상태가 확인되면 다음 포트로 진행합니다. 확인이 끝내 실패하면 결과에서 처음 확인하지 못한 포트와 이후 명령을 보내지 않은 포트를 볼 수 있습니다.
* **Power OFF**는 스위치가 PoE 사용 설정을 확인한 포트에서 실행할 수 있습니다. 물리 링크가 Down이거나 LLDP에 AP 이름·모델이 없을 때도 선택한 포트의 전원을 끌 수 있습니다. 여러 포트의 데이터 링크를 비활성화하려면 **제어 옵션 → 작업 → 포트 비활성화 (Disable)**를 고르고 대상 포트를 선택하세요. 링크가 Down이거나 전력값·LLDP 정보·포트 조회 결과가 없어도 선택할 수 있습니다. **제어 대상과 명령 검토**에서 스위치 주소와 포트 목록을 확인한 뒤 실행하세요.
* **전력 공급 변경 후 전력 확인**은 빠른 제어와 일반 제어에서 자동으로 진행됩니다. 결과에서 변경 전 전력과 재조회한 전력(W)을 비교하세요. 두 시점 모두 실측값이 있을 때 차이를 표시합니다. 재조회 시점에 AP가 부팅 중이면 이후 소비 전력은 달라질 수 있습니다.
* **케이블 진단**은 **포트·PoE 관리**의 스위치 주소, SSH 포트와 물리 포트 선택을 사용합니다. 진단을 실행하면 해당 스위치 전체의 이전 케이블 측정값을 한 번 지웁니다. 이어 선택한 포트마다 테스트를 실행하고 이번 검사에서 확인된 결과를 표시합니다. 검사 중 선택 포트의 링크가 잠시 끊길 수 있으므로 실행 전에 대상을 확인하세요. 확인 질문 없이 측정표 또는 완료 응답을 보내는 장비에서도 이어서 결과를 조회합니다. 결과가 늦으면 해당 포트의 결과 조회만 반복합니다. 테스트 승인 뒤 또는 결과를 읽는 도중에 SSH 연결이 끊기면 해당 포트에서 한 번까지 같은 장비에 다시 연결해 결과를 읽습니다. 이때 초기화와 테스트를 다시 실행하지 않습니다. 확인된 페어부터 표에 표시하고, 아직 읽지 못한 페어는 **값 미수신**으로 표시합니다. 진행 중이거나 측정값이 없는 페어는 완료 개수에서 제외합니다. 장비가 해당 포트에 결과가 없다고 명시하면 앞서 표시한 부분 측정값도 지웁니다. 초기화·테스트·결과 조회 중 어느 단계에서 멈췄는지도 확인할 수 있습니다. 불완전한 응답을 확인하려면 실행한 화면에서 **이번 응답 보기**를 펼치세요. 표에는 스위치가 보고한 선 쌍별 상태와 케이블 길이 또는 장애 지점까지의 추정 거리가 표시됩니다. 예를 들어 `Open`은 단선 또는 케이블 미연결을 뜻합니다. [HPE 2930F 케이블 진단 안내](https://arubanetworking.hpe.com/techdocs/AOS-S/16.11/MCG/WC/content/kb/cab-dia.htm)
* **스위치 컨피그 백업**에는 스위치 IPv4 주소만 한 줄에 하나씩 입력합니다. 백업은 기본 SSH 포트 22로 연결합니다. 모델과 호스트 키를 확인한 장비에서 실행 설정을 읽습니다. 파일 이름 방식, 동시 접속 수, 최대 시도 횟수를 지정할 수 있습니다. 결과에서 장비별 TXT, Excel 보고서와 작업 로그를 내려받습니다.
* 작업 중에는 상단에 현재 단계를 표시합니다. 처리 수가 확인된 단계에는 완료 건수·전체 건수와 진행률이 나타나고, 전체 수를 알 수 없는 단계에는 대기 표시가 나타납니다.

**대상 목록 관리**에서 직접 입력, 스위치 행 편집, 표 붙여넣기 중 하나를 골라 같은 창에서 검증하고 적용하세요. 표는 기존 목록에 추가하거나 기존 목록을 교체할 수 있습니다. 대상 파일이나 JSON 프로필을 열어도 기존 조회 대상은 유지됩니다. 미리보기를 확인하고 **검증된 대상 적용**을 누르면 새 목록을 사용합니다. **결과 목록**에서는 행의 체크박스로 여러 포트를 선택합니다. 직접 지정한 포트와 매트릭스에서 선택한 조회 실패·재확인 대상은 **현재 상태 조회**로 읽을 수 있습니다. 빠른 PoE 제어 결과에는 실행한 포트와 이미 요청한 상태여서 건너뛴 포트가 표시됩니다. **화면 요소 식별**을 열면 입력한 값 없이 화면 요소의 고정 식별자로 수정 요청을 작성할 수 있습니다.

## 저장 위치

스위치 컨피그 백업에서 **폴더 선택**으로 위치를 고르거나 경로를 입력하면 해당 위치에도 날짜·실행 시각별로 결과가 저장됩니다. Windows 공유 폴더를 직접 지정한 경우에는 그 위치에 설정 파일도 복사되므로 공유 권한을 확인하세요. **결과 폴더 열기**를 누르면 Windows 탐색기에서 확인할 수 있습니다.

웹 버전의 데이터 폴더는 현재 Windows 사용자의 <code>%LOCALAPPDATA%\Aruba2930FLocalWeb\data</code>입니다. <code>outputs</code> 아래에 실행별 설정과 보고서가 저장됩니다. SSH 계정과 암호는 서버 메모리에만 보관합니다. 설정 백업 TXT에는 스위치가 출력한 설정값이 포함됩니다.

## 배포 구성

Windows 프로그램 v0.10.1의 Aruba 2930F 수집·제어 코어를 사용합니다. 배포본은 웹 화면, 로컬 HTTP 서버, Windows x64용 CPython 3.14.3 및 고정된 의존성을 포함합니다. 기본 접속 주소는 이 PC의 루프백입니다. 네트워크 공유를 켜면 선택한 네트워크 주소에서도 HTTPS 연결을 받습니다. GitHub 계정이나 인터넷 연결 없이 실행할 수 있습니다.
