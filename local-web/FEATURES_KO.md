# Aruba 2930F 기능 비교

v1.3.0에서는 **포트 조회 · 제어**와 **CSV 관제 · 비교**를 **포트 관제·제어**로 통합했습니다. 아래 표는 v1.2.0 당시의 위치를 기록합니다. AP 로그와 CSV는 실제 입력을 받을 때부터 관측값을 표시합니다.

**비교 대상**은 Windows EXE v0.10.1의 기본 진입점인 NetworkManagerWindow와 로컬 웹 v1.1.0입니다. 오른쪽 열에는 이번 웹 v1.2.0에서 같은 작업을 수행하는 위치와 동작을 적었습니다. EXE는 공식 Windows x64 ZIP의 SHA-256을 대조하고 포함된 실행 파일을 오프스크린으로 시작했습니다. 메뉴 동작과 예외 처리는 배포 태그의 소스와 테스트로 대조했습니다.

v1.3.3부터 로컬 웹은 첫 접속에서 장비별 SSH 지문을 자동 등록합니다. 같은 IP와 SSH 포트에서 지문이 바뀌면 접속을 차단합니다.

## 시작 · 세션 · 신뢰

| EXE에서 할 수 있는 일 | 웹 v1.1.0 | 웹 v1.2.0 |
|---|---|---|
| 홈에서 최근 백업·포트 작업 상태 확인, 해당 메뉴로 이동 | 바로가기만 제공 | **작업 현황**에서 최근 결과·시각과 진행 중인 작업 표시 |
| 라이트·다크 테마 전환과 선택 기억 | 제공 | 상단 전환 버튼과 로컬 브라우저 설정 |
| 공통 SSH 계정, 비밀번호, 선택적 Enable 비밀번호 적용·해제 | 제공 | **SSH 접속 설정**. 서버를 종료하면 계정 세션 종료 |
| 호스트 키를 먼저 확인하고 처음 보는 장비만 승인 | 별도 설정 화면 필요 | 백업·조회 중 지문을 대조해 승인 또는 건너뛰기. 승인한 장비는 같은 작업에서 계속 진행 |

| 저장한 호스트 키 열람·삭제, 변경된 지문 차단 | 개별 열람·삭제, 변경 차단 | 기존 Windows 지문 이관. 단일·여러 지문의 선택 제거, 변경된 키는 신규 승인 목록에서 제외 |
| 구형 SSH 협상과 비표준 SSH 포트 | 제공 | 기존 연결 코어 재사용. 백업 공통 포트와 장비별 포트 모두 지원 |

## 화면 진단 · 웹 관제

| 기능 | 웹 v1.1.0 | 웹 v1.2.0 |
|---|---|---|
| EXE의 선택형 화면 요소 식별 도구 | 없음 | 웹의 **화면 요소** 도구에서 요소 찾기·선택·요청용 식별 정보 복사 |
| 실행 파일의 버전·시작 진단 | 화면의 버전과 서버 상태 | 내장 런타임으로 `server.py --version`, `server.py --smoke-test` 지원. 시작 오류 진단 코드 제공 |
| AP 전용 포트의 로그 관제 | 제공 | 스위치 로그로 전력 미공급, 전력 공급 중 링크 끊김, 전력 공급 중 링크 연결 관측의 세 상태 표시 |
| 로컬 로그 파일·붙여넣기·SSH 로그 수집 | 제공 | 스위치별 원본을 전환해 같은 관제 화면에서 분석 |
| 기존 CSV 한 개로 관제와 우선 점검, 두 개로 변화 비교 | 제공 | **CSV 관제 · 비교**에서 열기. 현장 스위치 연결 없이 사용 가능 |

**운영 범위.** v0.10.1의 기본 화면에서 숨겨 둔 자동 OFF→ON 연속 재가동은 비교 대상에서 제외했습니다. 전원을 껐다 켜려면 두 동작을 각각 확인합니다. 브라우저에서는 데스크톱 창 분할선·Qt 위젯 대신 반응형 표·패널·대화상자를 사용합니다. AP 서비스 상태 표시는 스위치에서 관측한 전력과 유선 링크 기록 범위입니다.

**대조 근거.** 원본 태그 v0.10.1의 `manager_gui.py`, `gui.py`, `poe_query_gui.py`, `unified_port_gui.py`, `port_matrix_widget.py`, `port_control_gui.py`, `port_progress_panel.py`, `developer_inspector.py` 및 해당 테스트를 기준으로 삼았습니다. 웹 동작 검증에는 Windows x64, Chrome, 독립된 로컬 SSH 모의 장비를 사용했습니다. 물리 스위치와 실제 공유 폴더에 대한 현장 시험은 별도입니다.
