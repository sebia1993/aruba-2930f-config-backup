# Aruba 2930F 포트 통합 관리 — 2열 붙여넣기·전체 선택·PoE 재가동 (v0.6.0)

## 목표

실제 운영 시 **스위치 IP와 포트 번호만 엑셀에서 복사 → 조회 → 이상 포트/전체 포트 선택 → PoE OFF → 상태 확인 → PoE ON → 복구 확인** 흐름으로 사용할 수 있도록 한다.

기존 수집/제어 명령은 변경하지 않고, 검증된 PoE/LLDP 조회·단일/일괄 제어 서비스를 그대로 사용한다.

## 1. 엑셀 2열 입력 (기본)

다음처럼 엑셀의 두 열을 선택해 복사하면 된다.

```text
스위치 IP    포트
192.0.2.10   12
192.0.2.10   24
192.0.2.20   1/12
192.0.2.20   1/24
```

한 스위치의 포트를 쉼표로 구분해도 된다.

```text
192.0.2.10   12,24
192.0.2.20   1/12,1/24
```

- **IP·포트 2열 붙여넣기** 버튼은 SSH 설정을 접어도 화면에 표시한다
- **기존 목록 교체**가 기본이고, 필요한 경우에만 **기존 목록에 추가**를 선택한다
- 적용 전에 스위치/포트 수, 병합 결과, 원본 오류를 표시한다
- 동일한 IP·SSH 포트는 병합하고 같은 포트는 중복 제거한다
- 기본 SSH는 22, 기존 고급 3·4열 형식/저장된 JSON 목록을 유지한다
- 올바르지 않은 포트, IP, 입력 한도 초과, 기존 목록 추가 중 충돌은 반영하지 않는다
- 포트 범위, `all` 자동 확장, LLDP 장비 이름으로 IP를 추측하는 기능은 지원하지 않는다

## 2. 선택 범위

| 선택 범위 | 선택 결과 |
|---|---|
| 조회된 전체 | 검색·상태 필터 해제 후 등록된 결과의 포트 행 전체를 선택 |
| 현재 스위치 | 결과 표에서 선택한 스위치(또는 포트)의 소속 스위치에서 표시되는 포트만 선택 |
| 검색 결과 | 현재 IP·Hostname·포트·AP 검색 및 상태 필터와 일치하는 포트만 선택 |
| 제어 가능만 | 선택 범위에서 현재 지정한 포트 제어 동작의 검증 조건을 통과한 포트만 선택 |
| 재가동 가능만 | 현재 PoE ON + LLDP AP-535 확인 + Hostname/SSH 지문 확인 조건을 충족하는 포트만 선택 |
| 선택 해제 | 포트 선택 전체 해제 |

**전체 선택과 명령 전송은 완전히 별개**다. 제어 대상 수는 1회 최대 **300포트**, 조회는 최대 300스위치 / 14,400포트의 논리 한도를 유지한다. 301포트 이상을 제어해야 한다면 사용자가 조회 범위·작업 계획을 분할해 별도 승인한다.

LLDP에서 **모델 AP-535가 하나의 이웃으로 확인된 포트만** 일괄 PoE OFF/포트 Down 대상으로 허용한다. 단일 제어에서는 기존 개별 확인 절차를 사용한다.

## 3. 단계별 PoE 재가동

1. 대상 포트의 **실제 PoE 설정이 ON**, LLDP로 연결 AP-535가 확인되고, 장비 Hostname과 SSH 서버 키 지문이 조회된 상태에서 **PoE 재가동 시작**을 클릭한다
2. 기존 일괄 제어와 동일한 **PoE OFF 계획**을 만들고 대상 스위치/포트 목록과 `EXECUTE N` 문자열을 검토·입력해 승인한다
3. 포트는 한 개씩 작업하고 최대 10개마다 추가 승인을 받는다. 실제 장비의 상태·Hostname·SSH 지문은 명령 전 다시 검사한다
4. 작업 결과에서 **verified OFF**인 포트만 원래 스위치 IP·인터페이스·Hostname·지문과 함께 메모리에 보존한다. 명령 결과가 불확실한 경우 해당 계획의 재가동 마법사를 중단한다
5. **OFF 완료 · 재조회**를 눌러 실제 포트별 PoE OFF 상태를 새로 조회한다. LLDP가 끊겨 AP 이름이 사라져도 원래 IP·포트 조합은 유지한다
6. 확인된 OFF 포트만 **PoE ON 계획 만들기**를 통해 새 계획으로 작성한다. 전력 설정/Hostname/SSH 지문이 달라졌거나 조회가 실패하면 계획을 차단한다
7. 작업자의 **별도 `EXECUTE N` 승인** 후 ON 명령을 전송한다. 앞선 OFF 승인만으로 ON을 자동 실행하지 않는다
8. **ON 완료 · 복구 재조회**로 실제 PoE ON 상태를 조회해 확인한다. 여기까지 확인돼도 무선 서비스 정상 여부는 WLC/AP 상태로 별도 검증한다

OFF 성공/미실행이 혼재하면 **검증된 OFF 대상만** ON 계획으로 넘긴다. PRECHECK 실패·미실행·결과 불확실 포트는 제외 또는 수동 조사 대상이므로 화면과 작업 이력에서 반드시 확인해야 한다.

## 4. 중단·복구 안전성

- **자동 재시도, 자동 ON, 자동 롤백, `write memory`는 없음**
- 일괄 작업은 기존 `port-control/batch/<plan_id>.jsonl`에 계획/명령 전 intent/결과를 fsync로 기록
- ON은 OFF와 **다른 계획 ID·다른 독립 이력**을 사용
- PC 종료·실행 실패·불확실한 상태에서는 마법사를 자동 재개하지 않음. 실제 스위치 PoE를 수동 재조회하고 필요한 ON 명령을 운영자가 개별 승인
- 전체 OFF 후 전체 ON 방식은 AP 서비스에 광범위한 영향을 줄 수 있음. 장비별·서비스별 영향 범위를 확인해 적은 포트 단위로 실행 권장
- 포트 전력 협상/설정 확인은 AP·사용자 인증·SSID의 서비스 정상 보장과 다름
- 저장된 대상 목록과 설정 파일에 SSH/Enable 암호를 기록하지 않음

## 5. 자동 검증

- 다양한 한글 2열 헤더, 중복 IP/포트, 잘못된 행, 교체/추가 동작의 원자성
- 전체·현재 스위치·필터 범위 선택과 위험 포트 제외
- 300포트 한도, 실행 전 승인, OFF/ON별 독립 계획
- OFF 이후 재조회 없이는 ON 계획 생성 불가
- 장비/지문/PoE 상태 변경 시 ON 차단
- 부분 작업·취소·결과 불확실 시 수동 확인 경로
- UI 윈도우와 포터블 EXE 스모크 테스트

자동 검증과 문서 캡처는 가상 데이터이며 실제 네트워크 장비의 PoE 전력 제어를 검증한 것은 아니다.

## v0.8.0 개발용 두 버튼 원칙

사용자가 포트를 체크한 뒤 선택하는 전원 제어 버튼은 **PoE OFF 즉시 / PoE ON 즉시** 2개만 남긴다. 중복되는 재가동 버튼 및 재가동 상세 설명은 기본·고급 화면에서 숨긴다. 재가동은 필요한 경우 작업자가 OFF 이후 상태를 확인하고 ON을 별도로 눌러 수행한다. 기존 안전 검증과 실패 시 중단·이력 기록은 동일하다. 사용자가 이 화면을 승인하기 전까지 main 병합/릴리스를 진행하지 않는다.

## 기본 화면 사용 방법 (v0.7.0 사용자 검토안)

일반 작업은 IP·포트 입력/조회 → 포트 체크 → 하단 **OFF 즉시·ON 즉시·재가동** 세 단추로 진행한다. `작업 계획` 버튼과 `EXECUTE N` 문구를 요구하지 않는다. 상태·작업 중지 버튼도 하단에 표시된다.

고급 기능이 필요한 경우에만 **고급 제어 · 단일 포트 / 기존 계획 기능**을 열어 포트 Up/Down, 별도 계획 작성과 반복 승인을 사용할 수 있다. 기존 함수와 엔진은 제거하지 않았다.

다중 PoE OFF의 취소 가능한 한 번 확인, SSH 계정, 최초 신뢰하지 않은 SSH 장비 지문, 실행 직전 모델·대상 확인, 실패 시 자동 재시도 금지는 그대로 유지한다. 입력이 비어 있는 경우 같은 프로그램의 백업 화면에서 이미 입력한 인증 정보를 메모리 내에서 재사용할 수 있다.

## v0.7.0 B안 — 체크박스 작업 흐름 (개발 브랜치 전용)

1. 스위치 체크박스 또는 포트별 체크박스로 작업 대상을 지정한다. 행 클릭 자체는 작업 선택이 아니다.
2. 범위: 등록된 전체 / 현재 스위치 전체 / 검색 결과에서 보이는 포트.
3. 검색·필터 변경에도 체크 상태는 유지되고 하단 제어 바는 체크 수와 숨긴 체크 수를 표시한다.
4. **빠른 OFF·ON 버튼은 별도의 작업 계획 조작과 EXECUTE N 문구 입력을 요구하지 않는다.** 내부 BatchPlan은 자동 생성·고정하고 즉시 실행한다. 다중 포트 OFF에 한해 취소 가능한 확인창을 한 번 표시한다. 빠른 실행 경로에서는 10포트 단위 추가 확인을 생략하지만 매 포트의 장비 식별/사전 검증/작업 이력 기록/결과 불확실 시 중단은 그대로 적용한다. 고급 일괄 계획 메뉴에는 기존 EXECUTE N 및 10포트 단위 재승인을 계속 제공한다.
5. 조회 누락·차단 포트가 하나라도 있으면 임의로 제외하지 않고 계획 전체를 거부한다.
6. 재가동 버튼은 PoE OFF 별도 승인 → 수동 상태 재조회 → PoE ON 별도 승인 → 복구 재조회의 상태 전이를 그대로 유지한다.
7. 작업 실행 중과 활성 재가동 단계에서 체크박스·대상 입력·일반 필터·재조회 버튼을 잠근다.
8. 기존 일괄 변경 한도 300포트, SSH 지문·Hostname·PoE 상태 재검증, 작업 중 10개마다 승인, JSONL 로그의 불확실한 결과 시 자동 재시도 금지 정책을 유지한다.

이 개발 버전은 실제 프로그램에서 캡처한 HTML 검토 전까지 main 병합 및 GitHub 릴리스 발행을 하지 않는다.
