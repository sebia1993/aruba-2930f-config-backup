# Aruba 2930F 포트 통합 관리 (v0.4.0 개발 브랜치)

## 목적과 지원 범위

기존 [다중 포트 전력·LLDP 조회](POE_QUERY_KO.md)와
[단일 포트 제어](PORT_CONTROL_KO.md)를 한 화면에서 사용합니다.
백업의 읽기 전용 경계는 그대로 유지합니다.

- 등록: 스위치 IP / 인터페이스 목록, 기존 고급 SSH 포트·별칭 유지
- 최대 300개 SSH 접속 대상, 대상당 최대 384개 명시 포트, 전체 최대 14,400포트
- 지정 포트의 링크·PoE 실측(W)·AP 이름(LLDP)·AP-535 공급·협상 판정 조회
- 기존 JSON v1 불러오기와 CSV 내보내기 호환
- 다중 행 선택 후 한 종류의 명령(PoE ON / OFF / 포트 Up / Down)으로 계획
- 한 번의 실행 계획에 최대 300개 포트. 300개 스위치 조회 제한과 별개입니다
- 일괄 설정 변경은 단일 포트 서비스의 기존 명령만 사용하고 자동 재시도하지 않습니다

## 사용 흐름

1. 메인 화면의 **포트 통합 관리…**를 엽니다.
2. 스위치 IP와 조회할 인터페이스 목록을 입력하거나 JSON/엑셀 목록을 불러옵니다.
3. 전체 또는 선택 스위치·포트 조회를 실행합니다.
4. **검색·필터**에서 스위치 IP/호스트네임/AP 이름/인터페이스를 찾거나 조회 실패·전력 확인 필요·PoE 꺼짐을 추립니다. Ctrl/Shift로 대상 포트를 선택합니다.
5. 네 동작 중 하나를 선택하고 **작업 계획**을 만듭니다.
6. 전체 IP:SSH포트/인터페이스/호스트명/AP 이름 미리보기를 검토합니다.
7. 확인 문자열 **EXECUTE N**을 정확히 입력해야 실행됩니다.
8. 작업은 한 포트씩 실행하며 10개 처리 후 다음 묶음 승인을 요청합니다.
9. 진행 상황과 결과를 확인하고, 작업한 포트는 다시 조회해 최신 전력·LLDP 값을 확인합니다.

실제 변경 전에는 대상으로 선택한 포트를 다시 조회해 IP, SSH 지문, 스위치
호스트네임, 포트 사용 설정 및 PoE 설정을 원래 조회 결과와 비교합니다.
값이 다르면 해당 작업을 건너뛰고 기록합니다. 앞선 결과가 불확실하면
후속 작업을 중단합니다.

## 위험 작업 기본 보호

- PoE OFF 및 포트 Down의 **일괄 변경**은 조회 당시 LLDP에서 AP-535로
  확인된 포트만 허용합니다. AP 이름만으로 장비 종류를 추정하지 않습니다.
- LLDP 이웃 없음/모델 확인 불가/다중 이웃/스위치 등 비-AP 장비가 확인된
  포트는 파괴적 일괄 작업을 차단합니다.
- 포트 Up 및 PoE ON도 사전 상태 확인과 작업 승인 및 변경 후 검증을 통과해야 합니다.
- LLDP가 없는 포트나 일반 스위치 포트를 변경해야 한다면 **선택 포트 단일 제어…**
  에서 기존 개별 확인 절차를 사용합니다.
- LLDP는 장비가 광고하는 정보이므로, 한 번의 결과만으로 관리 링크·업링크를
  완벽하게 분류할 수 없습니다. 운영자는 실제 배선과 서비스 영향을 별도로 검증해야 합니다.
- 작업당 한 종류의 변경만 허용하고, PoE OFF 후 자동 ON이나 포트 Down 후
  자동 Up, 자동 재시도·자동 롤백은 구현하지 않습니다.
- 장비 변경은 running-config에만 적용되며 write memory를 수행하지 않습니다.

## 대기열, 변경 결과, 취소, 복구

일괄 제어는 기본 병렬도 1로 실행합니다. 각 포트는 새 제어 서비스 인스턴스로
검증하므로 이전 포트의 단일 조회 snapshot과 상태가 섞이지 않습니다.
연결 실패·상태 변경 등 명령 전 오류는 그 포트의 preflight_failed로 기록합니다.
명령을 전송했지만 결과가 불확실한 경우는 unverified로 기록하고 남은
작업을 paused로 처리합니다.

- verified: 변경 후 설정 확인 완료
- unchanged: 이미 요청한 상태여서 명령 미전송
- preflight_failed: 변경 전 대상·상태 확인 실패, 명령 미전송
- unverified: 전송 여부 또는 결과 확인 불가, 자동 재전송 금지
- paused: 다음 처리 묶음이 승인되지 않았거나 이전 작업이 불확실하여 미실행
- cancelled: 사용자 중지 요청 후 아직 명령을 보내지 않은 포트

일괄 작업 이력은 로컬의 port-control/batch/<계획 ID>.jsonl에 순서대로 기록됩니다.
각 작업 전 preflight, **명령 보내기 전 intent**, 후속 result를 fsync로 기록하며
파일을 만들지 못하면 어떤 변경도 시작하지 않습니다.

프로그램/PC가 비정상적으로 종료돼 intent만 남았다면 기록 판정은
result_unknown이며 자동 재실행하지 않습니다. 읽기 전용 복구 조회로
마지막 기록을 확인할 수 있습니다. 작업 재개는 **미실행 대상도 새 계획과 새 승인**이
필요하며 이전 계획을 자동으로 재전송하지 않습니다.

일괄 제어는 실행 파일이 로그 파일을 쓸 수 있어야 시작합니다. 이력에는
IP, 포트 번호, 호스트네임, AP 이름, 동작과 결과가 담길 수 있지만
SSH 비밀번호와 Enable 비밀번호는 기록하지 않습니다. 사내 업무자료로 관리하십시오.

## 대규모 조회 정책과 검증

기본 조회 동시 접속은 기존과 같은 3대입니다. 스위치 한 대의
show interfaces brief 결과는 한 번만 읽고 선택된 포트를 매핑합니다.
포트별 PoE와 LLDP는 각 지정 포트만 조회합니다. 스위치별 독립 세션과
부분 오류 격리를 유지합니다.

300대 x 48포트 = 14,400포트의 합성 대상 생성/검증을 자동화합니다.
이 수치는 지원 가능한 **논리적 한도**이며 실제 장비 처리시간이나 CLI
호환성, 장시간 메모리 사용량과 네트워크 부하가 실측으로 검증됐다는 뜻이 아닙니다.
실제 현장 테스트는 사용자가 수행합니다.

## 릴리즈 경계

v0.4.0은 신규 기능 개발 브랜치의 버전이며, CI 통과 전에는 배포 완료로
간주하지 않습니다. 기존 v0.3.0 사전릴리즈는 별도 유지합니다.
