# 로컬 웹 자동 조회·수동 예약 안정화 검토 (2026-11-23)

## 목표 및 적용 범위

- 기준 배포: 로컬 웹 `web-v1.30.1`, Windows 데스크톱 `v0.11.0`.
- 자동 수집(기본 1분)과 케이블 진단·PoE OFF/ON 수동 예약의 **순차 실행, 작업 결과의 불확실성 처리, 사용자 화면 복원**을 유지한다.
- 실제 Aruba 스위치 연결 시험은 이번 개발·CI 작업 목록에 포함하지 않는다. 검증 결과는 가상 SSH/Windows 자동 테스트 범위로만 기술한다.
- 기존의 SSH 지문 검증, 인증 전 제한적 호스트키 재협상, 장비 변경 명령 자동 재전송 금지 정책을 유지한다.

## 이번에 강화한 경계

1. 케이블 진단 진척 조회가 비정상 값을 반환하거나 커서가 진행되지 않으면, 더 이상 반복 조회하지 않고 관련 포트의 결과를 **불확실**로 처리한다. 동일 포트에 예약한 후속 제어는 자동으로 실행하지 않는다.
2. 장비 명령을 처리한 뒤 결과 분석기가 예상치 못한 예외를 발생시키더라도 예약 실행 스레드와 정리 절차를 종료하지 않는다. 해당 작업을 **불확실**로 기록하고 동일 포트의 예약을 취소하되 다른 포트의 안전한 예약은 이어서 처리한다.
3. 서로 다른 스위치의 포트를 포함한 다건 예약이 접수순으로 실행되고 자동 모니터링 새 회차보다 우선 처리되는지 검사한다. 자동 조회가 밀린 회차는 누적 실행하지 않고 `건너뛴 조회`로 집계한다.
4. 서버 재시작, 세션 변경, 예약 대기 시간 초과, 취소·중복 요청 때 기존 **다시 실행하지 않음** 정책을 유지한다.

## 호환성 검토와 열린 PR

- [#28](https://github.com/sebia1993/aruba-2930f-config-backup/pull/28): 데스크톱 Paramiko 4.0.0 → 5.0.0 업데이트 제안.
- [#59](https://github.com/sebia1993/aruba-2930f-config-backup/pull/59): 로컬 웹의 동일 업데이트 제안.
- 5.0.0은 일부 SHA-1 기반 KEX를 제거한다. WC.16.01.0008 연결 성패를 추정하거나 SSH 알고리즘 허용 범위를 넓히지 않는다.
- 두 배포본의 Paramiko 4.0.0 고정 및 **서버 호스트키 `ssh-rsa` 예외만** 허용되는 조건을 테스트한다. 따라서 #28, #59를 현재 작업에서 병합하지 않는다. 업그레이드는 별도 호환성 브랜치에서 진행한다.
- [#56](https://github.com/sebia1993/aruba-2930f-config-backup/pull/56)은 이전 Windows UI 매트릭스/테마 브랜치다. 최신 `main`의 반응형 화면과 기능이 겹치는지 별도 대조가 필요하므로 기존 PR을 임의 병합·종결하지 않는다.

| 케이블 진단 진행 커서가 멈춤/형식 오류 | 스레드 무한 대기 없음; 불확실 포트의 후속 제어 차단 |

| Windows CI 및 ZIP | 전체 단위 테스트, 로컬 웹 브라우저 예약 테스트, 배포 패키지 기동·해시 점검 |

## v1.30.3 추가 개선: 작업 종료 후 표시 실패 복구

- 관측값을 전력 이력·포트 매트릭스에 반영하는 단계가 예기치 않게 실패해도 단일 실행 슬롯을 반드시 해제하도록 예외 처리를 추가한다.
- **PoE 명령 이후** 결과 반영에 실패했다면 실제 변경 여부를 알 수 없으므로 해당 작업의 이력을 `uncertain`으로 남기고 동일 포트에 예약된 후속 작업을 취소한다. 다른 포트의 안전한 예약은 계속 처리한다.
- 자동 모니터링 관측값 처리 중 장애가 나면 결과를 `failed`로 표시하고 기존 관측·제어 권한을 무효화한 후 다음 예약 주기에 복구를 시도한다. 임의 포트 제어 명령을 자동 재전송하지 않는다.
- 회귀 테스트: 결과 기록 중 가상 예외 발생, 모니터링 슬롯 회복, 예약 대기열 정리, 결과 미확인 상태 보존. 24시간 가상 시간 모니터링 주기 검사는 기존 테스트로 유지한다.
- 현장 장비 연결 검증은 이 작업 범위에 포함하지 않는다.

## 릴리스 판단

- 신규 기능을 추가하지 않는 안정화 작업이다. 자동 테스트 실패 시 병합·릴리스를 보류한다.
- 작업 범위가 기본 UI를 변경하지 않으므로 불필요한 레이아웃 변경·설정 메뉴 추가·전원 제어 정책 완화는 허용하지 않는다.
- GitHub PR에 자동 테스트 결과와 실패 수정 근거를 남긴 후 병합·버전 발행 여부를 판단한다.

## 2026-11-25 추가 보완: 케이블 진행 이력의 무한 증가 방어

- 취소된 케이블 진단의 진행 이력 생산자가 종료 신호 없이 **계속 증가하는 커서**를 반환하면 기존 이력 판별 반복문이 끝나지 않을 수 있다.
- 이력 조회를 최대 **128페이지**로 제한하고, 그 안에 종료 조건이 나타나지 않으면 관련 취소 대상 전체를 **결과 불확실**로 분류한다.
- 일부 포트의 실행 흔적만 보여도 이력이 잘린 경우 나머지 포트를 안전하다고 추정하지 않는다. 불확실 포트의 후속 PoE 제어는 기존 대기열 안전 정책에 따라 차단된다.
- 회귀 테스트는 진행 커서만 무한히 증가하는 모의 응답에 대해 반복 횟수가 제한되고, 미확인 포트까지 차단 대상으로 보존되는지 확인한다.
- 사내 장비 테스트는 사용자 직접 검증 영역으로 유지하고, Paramiko 5.0 업데이트 PR #28·#59 및 데스크톱 UI 초안 PR #56은 이 안정화 변경에서 건드리지 않는다.
- 코드 변경 및 검증 근거는 해당 GitHub PR의 체크포인트와 CI 실행 기록을 기준으로 추적한다.
