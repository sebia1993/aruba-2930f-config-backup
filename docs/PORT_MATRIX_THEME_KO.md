# Aruba 2930F 포트 독립 매트릭스와 라이트/다크 테마 설계

## 설계 기준

- 기준 브랜치: `main` `934e853006da2cf96cfc1619078440f510a8f6fc` (v0.9.5 통합)
- 코드 구현: 네이티브 Windows PySide6. 기존 HTML은 시각적 참고용입니다.
- 1블록 = 1개 *명시적으로 등록한* 포트. 스위치 전면의 24/48개 전체를 자동 생성하지 않습니다.
- 스위치 300대, 전체 지정 포트 14,400개라는 기존 입력 한도를 수정하지 않습니다.
- 동일 포트 번호를 가진 서로 다른 스위치는 `(IP:SSH포트, 인터페이스)` 복합키로 구별합니다.
- 기본 정렬은 IPv4 주소, SSH 포트, 숫자형 인터페이스 순서입니다. 상태 변화는 원래 순서를 뒤섞지 않습니다.
- 여러 포트가 있는 스위치는 지정한 포트 수만큼 블록이 나타납니다.
- 블록 클릭은 조회 전용 상세 정보 열기이며 포트 제어 선택 체크박스 변경이나 명령 전송을 하지 않습니다.
- 작업할 포트 지정은 원래 `QTreeWidget` 체크박스와 `_checked_port_keys`만 사용합니다. 실제 PoE 제어는 기존 `_quick_poe_action`에서만 수행합니다.

## 화면 배치

1. 최상단: 기존 4개 메뉴 + 일회 클릭 `라이트`/`다크` 버튼 (시스템 자동 모드 없음)
2. 포트 통합 관리: IP/포트 입력 영역을 기존 `QSplitter`로 접기/확장
3. 조회 진행률: 기존 `PortProgressPanel`
4. 조회 결과: 위쪽 `PortMatrixPanel`, 아래쪽 기존 포트별 표를 세로 분할
5. 매트릭스: 가상화된 `QAbstractTableModel` + `QTableView`/커스텀 delegate로 필요 셀만 페인팅
6. 클릭 시: 오른쪽 285px 읽기 전용 상세 패널 개방 (닫을 수 있음)
7. 상세 패널: 스위치 이름, IP, 포트 번호, Link, PoE 설정, 실측 W, LLDP AP, 관측 시각 및 우선 확인 목록
8. 하단: 기존 PoE OFF/ON 두 버튼, 작업 진행률, 중지 및 기존 이력 기록 유지

## 분류의 보수적 해석

| 색상/상태 | 분류 조건 |
|---|---|
| 녹색·Link Up | 최신 실제 조회에서 관리 Enable 및 Link Up 관측 |
| 붉은색·Link Down | 설정 OFF가 아닌 상태에서 실제 Link Down 관측. 서비스 장애 확정으로 표시하지 않음 |
| 노란색·일부 확인 필요 | LLDP 수집 실패 또는 관련 평가 근거 확인 필요 |
| 파란색·설정 OFF | 관리 Disable 또는 PoE 설정 OFF (Link Down과 구별) |
| 회색·미수집 | 미조회, SSH/결과 실패, 측정 근거 없음 |
| 보라색·조회 중 | 새 읽기 전용 조회/수집 진행 중 |

실측 W의 `0 W`를 단독으로 전원 장애로 판정하지 않습니다. LLDP 이웃이 없다고 곧바로 AP 장애로 판정하지 않습니다. 포트 상태·PoE 설정·LLDP 조회 상태는 상세 영역에서 서로 구분합니다.

## 절대 유지할 기존 제어 정책

- SSH 서버키 SHA-256 신뢰 검증, 변경 지문 차단 및 WC.16.01 자동 호환성 로직
- 여러 포트 PoE OFF 명령의 단일 확인 절차
- 변경 직전 최신 상태 검증, AP-535 안전 정책, 변경 감사 JSONL
- 결과 불확실 시 중단 및 변경 명령 자동 재전송 금지
- 예약 PoE 제어, 자동 OFF/ON, `write memory` 기능을 추가하지 않음
- 백업 수집·CSV/JSON 입출력 형식, 세션 SSH 계정, 작업 이력 유지

## 자동 테스트 계획

- 1, 2, 다수 포트의 독립 블록/숫자형 인터페이스 정렬
- 포트 0 W, 미수집/조회 실패, LLDP 실패, 계획된 OFF, 실제 Down 분류
- 최대 300 × 48 = 14,400 포트 가상 모델 구성
- 셀 클릭 시 기존 표 선택만 이동하고 `_checked_port_keys`는 변경하지 않음
- 기존 4개 메뉴 유지 및 라이트/다크 원클릭 QSettings 동기화
- 전체 기존 pytest/Ruff/mypy/Windows x64 패키지 CI 회귀

## 배포 경계

이 브랜치에서는 제품 기능/디자인 개발만 하고 `main` 병합과 정식 릴리스는 수행하지 않습니다. 실제 Aruba 장비 SSH/PoE 현장 검증은 사용자가 별도로 수행합니다.
