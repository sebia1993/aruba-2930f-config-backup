# WC.16.01.0008 SSH 자동 호환 연결 안내 (v0.9.5)

## 변경 사항
이전 v0.9.4에 있던 `레거시 SSH (장비별)` 버튼과 별도 예외 승인창을 제거했습니다. 지금은 다른 스위치와 동일하게 **전체 조회**를 실행하면 구형 SSH 서버키 호환을 자동 처리합니다. 사용자 측에서 별도의 레거시 예외를 선택할 필요가 없습니다.

## 프로그램 실제 동작
1. 모든 스위치는 `ssh-rsa` 서버키 서명을 비활성화한 강한 SSH 방식으로 먼저 **서버 공개키만** 탐색합니다.
2. `IncompatiblePeer (no acceptable host key)` 또는 호스트키만 불일치한 것이 확인되면 기존 TCP 연결을 종료하고 별도 새 연결에서 한 번만 `ssh-rsa` 서버 호스트키 서명을 허용합니다.
3. 두 번째 사전 탐색에서 SSH 서버 공개키를 성공적으로 받으면 해당 스위치 IP:SSH 포트에만 호환 정보를 현재 프로그램 메모리에 기록합니다.
4. 처음 접속한 스위치의 서버 공개키는 **기존 SSH 서버 지문 승인창**에서 별도로 신뢰 확인합니다. 이미 등록된 키와 지문이 다르면 무조건 차단합니다. 신뢰 확인이 된 후에만 실제 사용자 이름·비밀번호를 보냅니다.
5. 포트 및 LLDP 결과를 수집하고, 자동 호환으로 연결된 포트는 PoE 상태 열에 **레거시 SSH**라고 표시하며 툴팁에서 SHA-1 서버 서명 사용을 안내합니다.
6. 정상 조회된 포트만 기존 보호 규칙에 따라 PoE ON/OFF 대상이 됩니다. 연결·변경 결과가 불확실하면 자동 재실행하지 않습니다.

## 현장 사용 방법
1. v0.9.5 Windows x64 ZIP을 다운로드하여 실행합니다.
2. 통합 화면에서 SSH 공통 계정을 입력하고 스위치 IP·포트 목록을 입력합니다.
3. **전체 조회**만 실행합니다. 수동 호환 모드 승인 작업은 필요 없습니다.
4. SSH 서버 지문을 처음 승인해야 한다면 장비 관리 기록·콘솔 등 **별도 신뢰 경로**로 SHA-256 지문을 대조합니다.
5. 조회 결과의 `PoE 상태` 열에서 `레거시 SSH` 표시 여부 및 포트별 LLDP/AP-535 상태를 확인합니다.
6. 조회 완료 후 `범위 전체 선택 → PoE ON 즉시`를 실행합니다. 이미 ON인 포트는 명령 대상에서 제외되며 상태 불확실 포트가 있으면 전체 변경이 보류됩니다.

## 보안상 중요한 제한
- 자동으로 허용하는 것은 **서버 호스트키 `ssh-rsa` 서명**뿐입니다. 사용자 공개키 인증 `ssh-rsa`는 차단 상태입니다.
- KEX의 `diffie-hellman-group1-sha1` 등을 추가로 허용하지 않습니다. **KEX 오류, cipher 오류, 접속 거부, 인증 실패**에는 자동 보안 하향이 없습니다.
- 자동으로 RSA/SHA-1을 재협상하면 중간자에 의한 **강등 공격** 가능성이 증가합니다. SHA-256 공개키 지문 고정은 이런 위험을 완전히 없애지는 못하므로 가능하면 장비 소프트웨어를 업데이트해야 합니다.
- 자동 재시도는 인증 전 서버 공개키 조회에만 적용합니다. 포트 제어/컨피그 변경 명령은 절대 자동 재전송하지 않습니다.
- 예외는 현재 실행 중 확인된 정확한 IP:SSH 포트에만 메모리에서 유지되며 SSH 공통 계정 변경·세션 해제·종료 시 초기화됩니다.
- 자동 테스트와 현장 SSH 로그인 성공은 별도 근거입니다. 개별 포트 PoE ON/OFF 및 LLDP 수집 성공은 추가 현장 결과로 확인해야 합니다.

## HPE 제조사 기술 근거
Aruba 2930F/2930M WC.16.08.0021에서 `rsa-sha2-256`, `rsa-sha2-512`, 추가 SHA-2 기반 키 교환 지원이 도입됐습니다. WC.16.01.0008은 더 이전 버전이므로 구형 호스트키 알고리즘을 요구할 수 있습니다. 실제 활성화된 알고리즘은 `show ip ssh`로 확인해 주세요.

## Paramiko 5.0 업그레이드 검토 (2026-11-23)
- 데스크톱 `requirements-lock.txt`와 로컬 웹 `requirements-runtime.txt`는 현재 Paramiko `4.0.0`에 고정돼 있습니다.
- Dependabot PR [#28](https://github.com/sebia1993/aruba-2930f-config-backup/pull/28), [#59](https://github.com/sebia1993/aruba-2930f-config-backup/pull/59)는 Paramiko 5.0.0 변경으로, upstream에서 SHA-1 기반 키 교환 알고리즘과 GSSAPI 지원을 제거합니다. 이것만으로 개별 장비의 협상 가능 여부를 단정할 수는 없습니다.
- 현재 자동 호환 경로는 *서버 호스트키의 ssh-rsa 서명*만 제한적으로 허용하며 **KEX·cipher의 보안 하향은 허용하지 않습니다**. 따라서 두 PR을 바로 병합하지 않고 현대식 접속, 인증 전 호스트키 재협상, 변경 지문 차단, 지원하지 않는 KEX의 실패 처리를 각각 독립 테스트한 뒤 업그레이드를 판단해야 합니다.
- 자동 테스트만으로 Paramiko 5.0 장비 호환성 확보를 선언하지 않습니다.
