# WC.16.01.0008 SSH 호환 연결 — 장비별 명시적 승인

## 문제와 제조사 근거
Aruba 2930F WC.16.01.0008 현장 테스트에서 SSH pre-auth handshake가 `SSH_ALGORITHM_INCOMPATIBLE`로 실패한다. HPE AOS-S 16.08 릴리스 노트는 WC.16.08.0021에서 `rsa-sha2-256/512` 서버 호스트 키와 추가 SHA-2 KEX를 지원하기 시작했다고 명시한다. 구형 장비가 `ssh-rsa`만 제공할 가능성이 높지만 정확한 실제 광고 목록은 `show ip ssh`로 확인해야 한다.
출처: https://arubanetworking.hpe.com/techdocs/AOS-Switch-RN/Content/16.08RN/WC/Enhancements.htm

## 요구 동작
- **기본**: 지금과 같이 모든 장비의 `ssh-rsa` 호스트 키 서명과 `ssh-rsa` 사용자 공개키 인증 차단.
- **옵트인**: 운영자가 사용 장비 IP:SSH 포트를 직접 선택하고 확인 문자열을 입력해 명시적으로 승인한 장비에서만 SSH **서버 호스트 키** 알고리즘 `ssh-rsa`를 일시 허용. 사용자 공개키 인증용 `ssh-rsa`는 계속 금지.
- 예외는 **현재 프로그램 세션의 endpoint allowlist**만 사용하고 디스크/Windows 사용자 설정 저장 금지. 계정 변경·세션 해제·프로세스 종료 시 전부 제거.
- 연결의 첫 단계(인증정보 전송 전)와 실제 Netmiko 연결에서 같은 장비별 정책을 사용. 알고리즘 불일치 자체가 자동 보안 하향을 트리거하지 않음.
- 기존 SHA-256 서버 키 지문 최초 승인/변경 차단은 예외 모드에서도 반드시 유지. 최초 키 승인 전 별도 경로로 서버 지문 확인 권고.
- `ssh-rsa` 이외 알고리즘(KEX, cipher)을 강제 약화하지 않으며 `diffie-hellman-group1-sha1` 등 취약 알고리즘 활성화 금지.
- GUI의 포트 통합 관리 검색 패널에서 "레거시 SSH (장비별)" 실행 → 명확한 위험 설명 및 대상 하나 선택 → IP:포트 정확한 입력 → 승인/해제 → 승인 시 해당 장비만 읽기 전용 재조회.
- 조회 실패 시 PoE ON/OFF 명령 전송 없음. 재조회/실행 안전 정책(LLDP AP535/300포트/SSH 지문/감사/미확인 전체 차단)은 변경 없음.
- 16.01 정식 현장 성공은 사용자만 검증 가능; 자동 테스트는 가상 서버/가짜 SSH 드라이버에서 정책과 안전 경계를 확인.

## 비범위
- 네트워크 장비의 SSH 설정 자동 변경, 펌웨어 업데이트 또는 Telnet 폴백.
- 전체 네트워크에 대한 묵시적 RSA/SHA-1 허용.
- CVE-2026-44405를 해결됐다고 표시하거나 Paramiko5로 강제 업그레이드.
