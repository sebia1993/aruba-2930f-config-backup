# 2930F 단일 포트 전원·통신 제어

## 요청과 범위

사용자가 기존 `aruba-2930f-config-backup`에 SW IP와 인터페이스를 입력하여
전원 또는 포트를 끄는 기능을 요청했다. 복구 동작도 같은 화면에서 제공한다.
Windows/PySide6 프로그램의 별도 `포트 제어` 창에서 단일 IPv4 스위치와 단일
실제 포트를 조회한 뒤 PoE OFF/ON 또는 포트 비활성화/활성화를 실행한다.
실장비 연결과 운영 검증은 개발 작업에 포함하지 않는다.

## 선택한 구현

- 기존 백업 SSH 세션의 읽기 전용 명령 허용 목록을 확장하지 않는다.
- 별도 서비스와 SSH 어댑터가 지문 검증·모델 식별·제한된 네 가지 명령을 담당한다.
- 별도 프로그램 방식은 배포와 접속정보 관리가 중복되고, 기존 백업 흐름에 변경
  명령을 섞으면 재시도 시 동작이 반복될 수 있어 별도 제어 창을 선택했다.
- 이는 요청을 구체화하기 위한 구현 판단이며, 사용자가 선택했다고 간주하지 않는다.

## 동작

1. SW IPv4, SSH 포트(기본 22), 계정/암호, 선택적 Enable 암호,
   인터페이스(예: `24`, VSF `1/24`)를 입력한다.
2. SSH 지문과 2930F 모델을 확인하고 실제 포트 목록 및 PoE 상태를 조회한다.
3. 포트 사용 설정/물리 링크/PoE 사용 설정/전원 공급 상태를 별도로 표시한다.
4. 사용자가 네 동작 중 하나를 고르고 화면에 표시된 대상 확인 문자열을 입력한다.
5. 실행 직전 다시 조회하여 대상과 설정이 변하지 않았는지 확인한다.
6. 허용된 명령을 한 번 전송하고 관리 설정을 재조회하여 결과를 표시한다.

## 제약

- 범위/여러 포트/임의 CLI를 입력할 수 없다. 장비 출력의 정확한 포트 ID를 사용한다.
- 지문 변경, 다른 모델, 불명확한 출력, 만료된 조회는 변경 전 중단한다.
- 통신 실패 후 변경 명령을 자동 재전송하지 않는다. 전송 후 확인 실패는
  `결과 확인 불가`로 표시하고 사용자가 다시 조회하게 한다.
- `write memory`는 실행하지 않는다. 자동 전원 재시작, 예약, 일괄 제어는 이번 범위 밖이다.
- PoE ON 확인을 AP/WLC 서비스 복구로 표시하지 않는다. PoE 미지원 포트에서는
  PoE 버튼을 사용할 수 없다.
- 관리 경로나 상단 연결 포트를 내리면 접속이 끊길 수 있음을 실행 확인에 표시한다.
- 암호는 메모리에만 유지한다. 작업 이력에는 대상·동작·전후 상태만 기록한다.
- 기존 백업 동작과의 동시 실행을 GUI에서 막고, 서비스에서도 중복 제어를 거부한다.
