# B안 2차 안정화 설계 (2026-11-18)

## 목적과 승인된 범위
운영자가 여러 Aruba 2930F에서 1~2포트씩 최대 300대까지 조회하고, 의도치 않은 AP 전원 차단을 피하며, 백업 TXT/XLSX/JSONL을 안정적으로 저장하도록 보완한다. PR #47을 기준으로 PR #46의 이미 검증된 네 개 파일을 통합한다. 사용자 승인 전 main 병합과 릴리스 금지.

## 유지 조건
- 백업 read-only, 포트 제어 GUI/명령·확인, 한 번 300포트, SSH 지문 고정, 비밀정보 저장 금지.
- 일괄 OFF/Down은 LLDP 단일 AP-535 (Chassis ID 및 상대 Port ID), fail-closed.
- 변경 명령 재시도·자동 ON·자동 롤백·write memory 금지.
- 실제 스위치 및 AP 검증은 사용자가 별도 수행. CI 합성 증거만으로 현장 적합성을 주장하지 않는다.

## 선택과 트레이드오프
1. **기존 2930F CLI와 포트 link 상태를 함께 확인 (채택):** 이미 조회 중인 `show interfaces brief`와 LLDP identity를 결합해, Link Down인데 캐시 LLDP만 남는 경우를 차단한다. 별도 긴 지연이나 추가 관리 프로토콜이 필요 없다.
2. LLDP 수신 프레임 카운터 증가를 기다려 강제 최신성 검증: 더 강한 근거가 될 수 있으나 AP 송신 주기만큼 최대 수십 초 이상 기다려 300포트 대량 작업에서 심각한 시간 증가 및 기종별 지원 문제 위험. 이번 범위에 포함하지 않는다.
3. 기존 Chassis ID 비교만 유지: Link Down에서도 캐시 이웃이 허용되는 문제가 남으므로 기각.

**한계:** Link Up과 일치하는 LLDP 결과도 캐시일 수 있으며, 교체된 장비가 막 연결된 상황의 완전한 최신성을 증명하지 않는다. 이 상태로 안전을 과장하거나 자동 제어를 확대하지 않는다.

## 오류 분류
- `PortControlService.apply`의 변경 전 링크·LLDP 검증에서 확실히 전송 전인 실패만 전용 typed 오류로 반환.
- 배치가 이미 `intent`를 써도 typed 실패는 `preflight_failed`로 기록하고, 이후 대상을 정책대로 이어간다.
- 다른 모든 일반 통신/쓰기 오류는 `unverified` 유지, 전송 여부 불명 시 자동 재시도·다음 포트 실행 금지. 실제 crash로 `intent`가 남아도 `result_unknown` 처리 유지.

## 성능과 보안
- GUI 결과 배치 렌더링을 전체 포트 수뿐 아니라 스위치 그룹 수에 따라 작동하도록 조정.
- 30/100/200/300대 × 2포트의 실측이 아닌 합성 회귀 테스트: 결과 보존, 배치 코얼레싱, 체크 상태, 취소 가능성.
- PR #46의 `poe_targets.py`, `reporting.py`, 관련 tests 네 파일을 기본 브랜치와 대조 후 동일 blob로 통합. 결과 의미·저장 경로는 유지.
- Paramiko 5.0은 별도 SSH/장비 호환성 검증 전 기존 pin 유지. 감사 예외의 보완 통제와 검증 기한을 문서화하되 무단 제거하지 않는다.
