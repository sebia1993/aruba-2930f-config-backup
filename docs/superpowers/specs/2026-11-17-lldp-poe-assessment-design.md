# LLDP와 AP-535 포트 전력 판정 — 승인된 수정 설계

사용자 승인: 2026-11-17 (Asia/Seoul), 대화의 수정 계획에 대한 “진행해.”
기반: `feat/grouped-poe-query`, `ad5eecdac9ad66ac8b24e20f150f26660954efdb` (PR #30).

## 사용자 동작

- 기본 대상 표는 스위치 IP와 스위치 인터페이스 목록 두 열이다. 여러 스위치에 각기 다른 여러 포트를 입력한다.
- SSH 기본값은 22. 고급 설정에서 기존 SSH 포트와 별칭을 보존한다. 불러온/상속한 비기본 포트는 숨기지 않고 고급 설정을 표시한다.
- 기존 3~4열 표와 JSON v1 파일을 계속 읽는다. 새 2열 TSV/인용 CSV를 지원한다. JSON v1의 `ssh_port`, `label`을 유지하며 자격 증명을 저장하지 않는다.
- 결과 그룹 제목은 `IP · 실제 스위치 호스트네임`. 비기본 SSH 포트와 별칭은 부가 정보로 보존한다.
- AP 이름 칸은 정상 LLDP 응답에서 이름 또는 `없음`. 조회 오류를 `없음`으로 위장하지 않는다.
- 포트별 현재 전력만 표시하며 스위치/전체 전력 합계를 만들지 않는다.
- 결과에 `공급·협상 정상`, 주의, 미공급, 오류, 확인 필요 등 PoE 판정과 근거를 제공한다. AP 전체 서비스 정상이라는 뜻으로 표시하지 않는다.
- 전체/스위치/포트 재조회와 중지, CSV 저장을 유지한다. 재조회 대상의 이전 PoE와 LLDP 결과를 지우고 새 결과를 수집하며, 다른 행과 시각은 유지한다.

## 수집 및 결과 보존

- 최대 3개 접속 대상을 병렬 처리하고, 각 대상은 한 SSH 세션에서 명령을 순서대로 실행한다.
- 각 스위치에서 선택 포트의 PoE를 먼저 읽은 뒤 같은 연결에서 LLDP를 읽는다. 두 스위치의 진행 단계가 같을 필요는 없다.
- PoE 단계 결과를 먼저 알리고, LLDP 결과를 같은 행에 추가한다. 포트 완료 여부와 PoE 성공 여부는 다른 값이다.
- LLDP 거절/파싱 오류/시간 초과/취소가 이미 수집한 PoE 값·시각·스위치 식별 정보를 지우지 않는다.
- 불확실한 SSH 전송 실패 후에는 세션을 닫고 미시도 작업의 상태를 기록한다. 자동 재접속·재시도·주기 감시는 추가하지 않는다.
- 포트별 실패가 모두 발생해도 앞서 얻은 호스트네임은 보존한다.
- LLDP는 요청한 정확한 Local Port와 결합한다. 상대 Port ID, 이름 또는 Chassis ID로 다른 로컬 포트의 결과를 연결하지 않는다.
- 선택 필드는 없을 수 있다. 이웃 0개와 해석 불가/CLI 실패를 구분한다. 여러 이웃은 내부적으로 모두 보존하며, 임의의 첫 이웃으로 AP-535 정상 판정을 하지 않는다.

## 제조사 기준과 판정

기준 문서: HPE 530 Series QuickSpecs `a00060238enw`, V22, 2026-08-17.

- AP-535의 단일 802.3at Class 4, IPM disabled 조건은 최대 23.3 W(외부 USB 제외). USB와 다른 Ethernet 포트에 제한이 있다.
- IPM enabled 조건은 예산·사용량에 따라 동적 제한을 적용할 수 있다.
- 802.3bt Class 5 또는 두 802.3at 전원을 shared로 사용하는 경우 전력 기능 제한 없이 동작한다. 해당 PoE 최대값은 26.4 W(외부 USB 제외).
- 802.3af Class 3 이하 전원 조건은 지원하지 않는다. Class 0~3 하나만으로 실제 af-only 공급이라고 추정하지 않는다.
- idle/deep-sleep 최대값 역시 정상 소비전력 하한이 아니다. 고정 W 범위나 임의 ±% 여유값으로 정상/불량을 판정하지 않는다.
- 다른 공식 데이터시트에 30/25 W 수치가 남아 있으며 조건도 다르다. 숫자를 혼합하지 않고 문서 버전을 기록한다.

실측 전력, 스위치 예약 전력, 포트 설정 상한, LLDP PD 요청/할당 전력은 별개다. 요청과 할당은 같은 협상 출처/기준과 단위의 유효한 쌍으로 비교한다. 빈 값·0·해석 불가를 충분한 할당으로 취급하지 않는다.

판정 우선순위:

1. 명시적으로 PoE가 꺼짐 → 공급 꺼짐. `Power Enable: Yes`와 `Disabled` 조합을 사용자 꺼짐으로 오인하지 않는다.
2. 현재 Fault/Other Fault → 공급 오류. Searching → 공급 대기. 미지원 포트 → 미지원.
3. 명확히 다른 AP 모델 또는 서로 충돌하는 근거 → 확인 필요.
4. 실제 지원 전원 협상 근거와 유효 요청/할당이 있으며 Delivering인 경우 요청 충족을 평가한다. 할당 < 요청이면 주의, 할당 >= 요청이면 공급·협상 정상(포트 기준).
5. 그 밖에는 확인 필요. 낮은 실측 W 자체는 부족 근거가 아니다.

공통 기준은 AP-535다. LLDP System Description에서 확인한 모델과 사용자가 지정한 AP-535 기준을 구분하여 `model_source`와 설명에 남긴다. 이름에 AP535가 있다는 이유로 모델을 확인했다고 하지 않는다. 실제 모델이 다르면 AP-535 기준을 적용하여 정상으로 표시하지 않는다. AP 내부 IPM·라디오 상태는 이번 스위치 전용 조회의 확인 범위가 아니다.

PSE Actual Power Value는 구형 문서의 LLDP 협상 문맥에 나타나지만 실측 전력과 혼합하지 않는다. 정확한 별칭 대응 근거가 없는 필드는 출처/문제를 보존하고 단독 정상 판정 근거로 쓰지 않는다. MED LLDP Detect가 Disabled여도 dot3 협상은 가능하다.

## Global Constraints

- Python 3.14, PySide6, 기존 잠금 의존성을 유지한다. 새 런타임 의존성을 추가하지 않는다.
- 기존 백업 및 PoE/인터페이스 변경 명령 권한과 확인 흐름을 확대하지 않는다.
- 실제 스위치·AP·컨트롤러에 접속하지 않는다. 장비 응답은 문서 구조를 참고한 가상 fixture로 검증한다.
- SSH 지문 확인, 출력 상한, 제한된 대기, 자격 증명 비저장, CSV 수식 방어를 유지한다.
- endpoint 정체성은 `(IPv4, SSH port)`다. 로컬 포트 `24`와 `1/24`를 동일시하지 않는다.
- 누락 전력은 빈 값/확인 불가이며, 실제 숫자 0과 구분한다.
- CSV는 포트당 한 행이다. 여러 LLDP 이웃 때문에 watts를 중복 출력하거나 합산하지 않는다.
- 화면의 장비 문자열은 일반 텍스트로 표시한다. 재조회 완료 전 이전 AP 이름을 현재 값으로 재사용하지 않는다.
- 선택 포트를 기존 제어창으로 자동 전달하는 기능, 과거 AP 기억, 자동 전원 조작은 이번 범위에 포함하지 않는다.

## 검증할 사용자 결과

- 두 열 입력과 기존 파일 왕복에서 SSH 2222·별칭이 유지되고 동일 IP의 다른 SSH 접속 대상을 합치지 않는다.
- 실측 8.7 W, 요청/할당 25.5 W인 문서형 응답을 낮은 소비전력 때문에 부족으로 판정하지 않는다.
- 요청 25.5 W/할당 20 W, 요청/할당 누락·0, 혼동되는 예약/설정 상한, 다른 모델, 충돌한 쌍은 올바른 상태로 구분된다.
- 정상 이름, 이름 없음, 이웃 없음, 조회 실패, 복수 이웃, 잘못된 Local Port가 정확히 처리된다.
- LLDP 실패·취소 후 완료된 PoE가 남고, 최종 진행률이 종료되며, 모든 포트 실패 후에도 호스트네임이 남는다.
- 선택 재조회 및 CSV에 예전 AP 이름·중복 전력·잘못된 시각이 남지 않는다.
