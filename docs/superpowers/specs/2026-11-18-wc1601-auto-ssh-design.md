# WC.16.01 자동 SSH 협상 호환 설계 (v0.9.5)

## 사용자 요청
v0.9.4의 `레거시 SSH (장비별)` 별도 예외 승인 버튼을 없애고, 기존 `전체 조회 → 포트 선택 → PoE ON` 흐름 내에서 구형 WC.16.01.0008 스위치에 자동으로 SSH 연결되게 한다.

## 구현안: 호스트키 불일치에 한정한 인증 전 자동 재협상
- 먼저 RSA/SHA-1 서버 호스트키/사용자 공개키 서명을 모두 차단한 기본 SSH 방식으로 **인증 정보 전송 이전**에 지문을 조회한다.
- 서버가 `IncompatiblePeer (no acceptable host key)`처럼 **호스트키 알고리즘 불일치**를 반환한 경우에만 TCP 연결을 닫고, 최대 1회 새 pre-auth SSH 연결에서 **서버키 `ssh-rsa`만** 허용해 공개키 지문을 확인한다.
- `no acceptable kex algorithm`, 인증 실패, Timeout, 접속 거부 등에서는 자동 보안 완화 금지. `diffie-hellman-group1-sha1` 및 약한 cipher 추가 허용 금지.
- 재조회에 성공한 정확한 IP:SSH 포트만 프로세스 메모리에 호환 모드 표기한다. 다른 스위치, 다른 SSH 포트에는 적용하지 않는다. 기본 조회가 성공한 장비는 호환 모드 표시 해제.
- **최초 서버 지문 승인 및 등록된 지문 변경 차단은 그대로 유지**, 사용자 공개키 인증에 대한 `ssh-rsa` 차단 유지. 호스트키 신뢰 검사 이전에 계정/암호 전송 금지.
- 기존 PoE 사전 검증, AP-535 LLDP OFF 보호, 300포트 제한, 결과 확인 불가 시 자동 재전송 금지 유지.
- v0.9.4의 수동 SSH 예외 버튼/확인창/파일과 관련 테스트를 삭제한다. 실행 상황은 결과 툴팁에 자동 호환 적용을 표시한다.
- 사용자가 별도 버튼을 누를 필요 없음. 초기 지문 신규 승인은 **일반 SSH 보안 승인**이며 구형 호환 예외 승인이 아니다.

## 검증
Paramiko fake와 실제 Paramiko/Netmiko 로컬 가상 Aruba SSH 서버에서 처음 strict 실패 → legacy pre-auth 재협상 성공 → 지문 승인 → 인증 연결 성공을 검증한다. 정상 장비는 strict만 시도하고, KEX 오류는 단일 실패로 종료한다. 작업은 독립 브랜치에서 CI 통과 후 v0.9.5 사전 릴리스만 배포한다. main 병합 금지.

## 리스크
`ssh-rsa` 서버 호스트키 서명은 SHA-1 기반이며 암호학적 위험이 증가한다. 자동 하향 협상은 적극적인 중간자에 의한 강등 시도 노출 가능성을 갖는다. 반드시 SSH 지문 고정과 변경 차단을 유지하고, 운영자는 가능한 펌웨어를 업그레이드해야 한다. 실제 WC.16.01.0008 장비 검증은 사용자 수행.
