# Aruba 2930F 설정 백업 검증 보고서

이 문서는 자동 테스트와 실제 Aruba 2930F 장비 검증을 **서로 다른 증거 수준으로 구분**해 기록하기 위한 문서입니다.

**2~7절의 읽기 전용 계정·구성 무변경 기준은 백업 기능에 대한 기준입니다.**
v0.2.0의 별도 포트 제어는 확인한 포트의 PoE 또는 사용 설정을 변경합니다.
포트 제어의 검증 범위는 9절에 구분하여 기록하며, 백업의 무변경 기준을 프로그램
전체에 적용하지 않습니다. Windows 패키지와 릴리즈 무결성은 해당 버전의 Actions
및 배포 자산 검증 결과로 확인하며 과거 버전의 결과를 새 버전에 그대로 적용하지 않습니다.
v0.3.0의 다중 스위치·포트 전력 조회는 읽기 전용이며 검증 범위는 10절에 기록합니다.

운영망 정보가 포함될 수 있으므로 외부 공개본에는 실제 IP, 장비명, 계정, SSH 장비 지문, 설정 원문을 기록하지 않습니다.

## 2. 백업 현장 검증 전 조건

실제 장비의 백업 검증은 다음 조건을 만족할 때만 수행합니다.

- 조직 정책상 자동 SSH 조회가 허용된 장비
- 설정 변경이 아닌 읽기 전용 점검이 허용된 계정
- 백업 파일을 안전하게 저장할 수 있는 점검 PC
- 장비 IP/호스트명/설정 원문을 외부 공개 자료에 포함하지 않을 수 있는 환경
- 테스트 중 문제 발생 시 즉시 중단할 수 있는 운영 절차

## 5. 백업 수집 결과 대조 방법

실제 장비 검증에서는 프로그램 결과만 보고 성공으로 판정하지 않습니다.

### 5.1 설정 파일 완전성

1. 프로그램이 저장한 TXT 파일 확인
2. 동일 장비에서 허가된 수동 `show running-config` 결과와 주요 구간 대조
3. 시작/종료부와 장비 hostname 등 식별 가능한 구조 확인
4. 페이저 문자열이나 잘린 마지막 줄이 없는지 확인

### 5.2 장비 상태

백업 검증 전후 다음을 확인합니다.

- 장비 재부팅 없음
- 설정 변경 없음
- 관리 접속 정상
- 운영 서비스에 이상 없음

백업 기능은 설정 변경 명령을 사용하지 않지만, 실제 백업 검증에서는
**읽기 전용이라는 설계 의도와 실제 동작이 일치하는지** 별도로 확인합니다.
별도 포트 제어의 의도된 설정 변경은 이 무변경 판정에 포함하지 않습니다.

## 8. 자동 검증과 현장 검증의 경계

자동 테스트는 다음을 강하게 보장하는 데 사용합니다.

- 입력/오류 처리 로직
- 명령 실행 순서
- 프롬프트와 페이저 처리
- 모델 식별 규칙
- 재시도 상태 전이
- 파일 저장과 보고서 생성
- 릴리즈 패키지 구조

반면 아래 항목은 실제 장비에서만 최종 확인할 수 있습니다.

- 특정 ArubaOS-Switch 버전의 실제 CLI 출력 차이
- 현장 SSH 정책과 암호화 알고리즘
- 특정 VSF 구성의 출력 형태
- 다수 장비를 대상으로 한 실제 네트워크 지연/타임아웃 특성

두 검증 수준을 혼합하지 않는 것이 이 프로젝트의 검증 원칙입니다.

## 9. v0.2.0 포트 제어 검증 범위

합성 장비와 오프라인 GUI 테스트에서는 다음 동작을 확인합니다.

- 단일 포트 입력 검증, 실제 조회 목록과의 일치, 잘못되거나 중복된 출력의 거부
- PoE OFF/ON과 포트 disable/enable 네 동작의 구분 및 관리 설정 재조회
- SSH 지문 변경, 대상 변경, 120초 조회 만료와 잘못된 확인 문자열에 대한 변경 차단
- 변경 명령 전송/재조회 실패 시 결과 확인 불가 표시와 자동 재전송 방지
- 실행 전 이력 저장, 암호를 포함하지 않는 작업 이력 및 중복 작업 차단
- 실행 중 제어 창과 부모 창의 종료를 막고 작업 완료 후 종료하는 GUI 동작

**실제 Aruba 2930F/VSF에서의 포트 제어 검증 상태: 미기록.** 합성 테스트 통과는
실제 포트 전원 차단, AP 재부팅, 컨트롤러 재등록 또는 무선 서비스 복구를 입증하지 않습니다.
해당 포트의 영향과 복구 경로를 확인한 승인된 현장 작업에서만 결과를 기록합니다.

| 현장 검증 구분 | 확인할 결과 | 현재 기록 |
|---|---|---|
| PoE OFF/ON | `Power Enable` 설정과 실제 전원 공급 상태를 각각 확인 | 미기록 |
| 포트 Down/Up | `Enabled` 설정과 실제 링크 상태를 각각 확인 | 미기록 |
| 관리 경로 단절 | 실제 적용 여부를 다시 확인하고 자동 재전송하지 않았는지 확인 | 미기록 |
| 저장 범위 | 포트 제어가 `write memory`를 실행하지 않는지 확인 | 미기록 |

수동 현장 결과에도 IP·장비명·배선 등 내부 식별 정보를 공개하지 않습니다.
포트 제어의 사용 방법과 프롬프트/출력 호환성 경계는 [PORT_CONTROL_KO.md](PORT_CONTROL_KO.md)를 참고하십시오.

## 10. v0.3.0 다중 스위치·포트 전력 조회 검증 범위

합성 전송 계층과 실제 오프라인 Qt 위젯으로 다음 동작을 확인합니다.

- 스위치별로 서로 다른 포트 목록 유지, 동일 IP의 서로 다른 SSH 포트 구분, 중복 제거
- 직접 입력과 표 붙여넣기, 잘못된 입력·목록 파일의 전체 거부, 기존 파일을 보존하는 저장
- 계정·암호를 포함하지 않는 JSON 대상 목록과 UTF-8 BOM CSV 결과
- 스위치당 한 세션, 최대 3개 스위치 동시 처리, 요청한 포트에 한정한 읽기 명령
- 지문 확인의 직렬화, 승인 대기 중 취소, 포트별 실패와 접속 대상 전체 실패의 구분
- 실제 0 W와 측정값 누락의 구분, 포트별 시각, 선택한 대상 재조회 시 이전 값 제거
- 작업 중 중지·조회 창 종료·부모 창 종료와 Qt 작업 스레드 정리
- 기존 백업과 단일 포트 제어의 회귀 검사 및 새 조회 창을 포함한 앱 실행 점검

자동 검사 결과는 [개발 기록](../DEVELOPMENT_LOG.md)에 실행 환경과 함께 기록합니다.
Windows EXE 포함 여부와 실행은 해당 버전의 CI·Release 작업에서 별도로 검증합니다.

**실제 Aruba 2930F/VSF 다중 전력 조회 검증 상태: 미기록.** 장비 접속 없이 생성한
화면은 UI 상태 표시의 증거이며 실제 전력값의 정확성이나 특정 펌웨어 호환성을 입증하지
않습니다. 현장에서는 스위치별 입력 목록과 CLI 출력, 포트별 시각, 일부 실패 시 다른
장비 결과의 보존, 중지 후 연결 정리를 확인하십시오. 같은 화면에 보이는 값도 포트별
측정 시각이 다르며 동시에 측정한 값이나 누적 Wh/kWh가 아닙니다.

사용 방법과 입력 예시는 [POE_QUERY_KO.md](POE_QUERY_KO.md)를 참고하십시오.

## 11. LLDP와 AP-535 공급 판정 확장

제조사 문서의 출력 구조를 참고한 가상 fixture와 오프라인 Qt 위젯으로 다음 동작을
검증합니다. 제조사 문서의 다른 AP 모델에 대한 예시 수치를 실제 AP-535 측정으로
주장하지 않습니다.

| 범위 | 검증할 결과 |
|---|---|
| 입력 호환성 | IP·인터페이스 두 열, 인용 CSV·TSV 헤더, 기존 3~4열·JSON v1, SSH 2222·별칭 보존 |
| 식별 정보 | IP 옆 실제 호스트네임, 모든 포트 조회 실패 시에도 이미 수집한 식별 정보 유지 |
| LLDP | 정확한 Local Port, 이름 없음/이웃 없음/실패 구분, 여러 이웃과 선택 필드 누락 |
| 숫자 근거 | 실제 W와 요청/할당·예약·상한 구분, 소수·단위, 누락/0/음수/중복/충돌 처리 |
| AP-535 판정 | 8.7 W 실측만으로 부족 판정하지 않음, 요청 25.5/할당 20의 부족, Class 4만으로 정상 추정 금지 |
| 모델·출처 | 설명에서 확인한 모델과 공통 기준 모델 구분, 다른 모델/복수 이웃/불명확한 전원 근거 보수적 처리 |
| 단계 보존 | 한 세션에서 PoE 먼저, 이후 LLDP; CLI 거절·시간 초과·취소 후 기존 전력 보존 |
