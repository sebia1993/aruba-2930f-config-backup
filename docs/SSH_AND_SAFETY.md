# SSH 수집 및 운영 안전

## 기본 원칙

이 도구의 **백업 경로**는 읽기 전용 설정 수집으로 제한합니다.
포트 제어는 아래에 명시한 별도 경로에서만 수행합니다.

핵심 원칙:

- 설정 모드에 진입하지 않음
- 장비 구성을 변경하는 명령을 실행하지 않음
- 모델 확인 전에 `show running-config`를 실행하지 않음
- 모든 연결에서 `no page`를 먼저 적용
- SSH 장비 지문이 변경되면 자동 수용하지 않음
- 불완전한 출력은 정상 백업으로 저장하지 않음

## 명령 순서

```text
SSH 장비 지문 확인
→ 로그인/EXEC 프롬프트 확인
→ no page
→ show version
→ show modules
→ 2930F 식별
→ show running-config
→ 최종 프롬프트 및 출력 검증
```

### `no page`

ArubaOS-Switch CLI에서 설정 출력이 페이지 단위로 멈추는 문제를 방지하기 위해 매 연결과 재연결에서 먼저 적용합니다.

`no page` 명령 자체가 정상 완료되었는지 확인하지 못하면 이후 `show` 명령을 보내지 않습니다.

예외적으로 페이지 표시가 남는 경우 제한적으로 처리하지만, 출력 시간·크기·행 수 한도를 넘으면 수집 실패로 기록합니다.

설정 배너 안에 페이지 표시와 동일한 문자열이 나타나면 실제 페이지 대기와 배너 본문을
구별할 수 없어 수집을 실패로 처리합니다. no page 적용 후에도 실제 페이지 대기가
배너 중간에 남는 경우에도 이 제한이 적용됩니다. 해당 문자열을 임의로 지우거나
잘린 설정을 정상 백업으로 저장하지 않습니다.

현재 보호 한도:

- 최대 출력 크기: 20 MiB
- 최대 행 수: 250,000행
- 명령 시간 제한 적용

## EXEC 프롬프트

최초 연결과 Enable 전환 후 확인한 EXEC 프롬프트를 이후 명령 완료 판정에 재사용합니다.

조회 명령의 에코를 확인하고 running-config의 배너가 닫힌 본문 뒤에서 최종
프롬프트를 확인합니다. 배너 내부의 동일한 프롬프트 문자열과 잠깐의 수신 공백은
명령 완료로 처리하지 않습니다. 닫히지 않았거나 형식을 확인할 수 없는 배너는
저장 전 검증에서도 거부합니다. SSH 수신 조각 사이에 나뉜 CRLF와 터미널 제어문자는
이어 붙인 뒤 정리해 수신 경계에 따라 백업 내용이 달라지지 않도록 합니다.

다음과 같은 설정 모드 형태는 허용하지 않습니다.

```text
switch(config)#
switch(vlan-10)#
```

공백, 괄호형 표시 래퍼 또는 `+`가 들어간 정상 EXEC 프롬프트는 처리할 수 있지만, 복잡한 프롬프트에서 호스트명을 무리하게 추정하지 않습니다.

프롬프트에서 장비 이름을 확인할 수 없으면 정상 수집된 `running-config`의 유일한 최상위 `hostname`을 보완값으로 사용할 수 있습니다. 두 위치 모두에서 확인하지 못하면 백업 파일명은 IP를 사용합니다.

## 모델/SKU 식별

다음 두 결과를 함께 사용합니다.

```text
show version
show modules
```

판정 원칙:

- 공식 2930F SKU가 확인되면 해당 모델로 기록
- 명확한 SKU 없이 2930F 계열 증거만 있으면 2930F로 처리
- 여러 공식 SKU가 확인되는 정상 2930F VSF는 지원
- 모듈/트랜시버 부품 번호를 섀시 SKU로 오인하지 않음
- 다른 장비 계열 또는 상충하는 명시적 SKU가 있으면 수집 차단

## SSH 장비 지문

처음 보는 장비는 SSH 인증 전에 서버 공개 키의 SHA-256 지문을 운영자에게 보여줍니다.

승인된 지문은 다음 위치에 저장됩니다.

```text
%LOCALAPPDATA%\Aruba2930FConfigBackup\known_hosts.json
```

여기에 저장되는 것은 로그인용 개인 키가 아니라 **장비가 제시한 SSH 서버 공개 키의 지문**입니다.

여러 프로그램 인스턴스가 같은 지문 저장소를 사용할 때 승인·삭제 작업을 파일 잠금으로
직렬화합니다. 잠금을 제한 시간 안에 얻지 못하거나 저장소를 읽을 수 없으면 오류를
표시하며 지문을 자동 승인하거나 저장소를 초기화하지 않습니다. 목록 삭제 중 오류가
나면 실제 저장된 목록을 다시 읽고, 이를 확인할 수 없는 경우에는 삭제를 중단합니다.

이미 승인한 장비에서 지문이 바뀌면 다음 가능성을 확인해야 합니다.

- 장비 교체
- SSH 키 재생성
- OS 재설치/초기화
- 접속 대상 IP 변경
- 중간자 공격 가능성

운영 기록과 대조하기 전에는 새 지문을 임의 승인하지 않는 것을 권장합니다.

## 자격증명 처리

다음 값은 세션 전용입니다.

- 사용자 이름
- SSH 암호
- Enable 암호
- 장비 목록

암호와 Enable 암호는 설정 파일, `operation.jsonl`, 백업 TXT 메타데이터에 저장하지 않습니다.

설정 TXT 자체에는 실제 네트워크 구성이 들어 있으므로 별도 보호가 필요합니다.

## SSH 알고리즘 안전 경계

일부 2930F는 다음과 같은 오래된 SSH 방식만 제공할 수 있습니다.

- `ssh-rsa`
- `diffie-hellman-group14-sha1`

기본 접속 경로는 Paramiko의 호스트 키 알고리즘(`keys`)과 공개 키 인증 알고리즘
(`pubkeys`)에서 `ssh-rsa`를 모두 비활성화합니다. 서버 호스트키만 불일치하면
인증 전 새 프로브 연결에서 해당 IP:SSH포트의 서버키 `ssh-rsa`를 한 번 시도합니다.
사용자 공개키 인증의 `ssh-rsa` 차단과 지문 등록·변경 감지는 그대로 적용됩니다.

**v0.9.2까지의 main**은 `ssh-rsa`만 제공하는 장비에 대해 인증 전에
`SSH_ALGORITHM_INCOMPATIBLE`로 중단했습니다. **현재 main v0.9.5**는
서버 호스트키 협상 불일치(`no acceptable host key`)에만 인증 전 TCP 연결을 닫고
1회 새 연결로 서버키 `ssh-rsa`만 자동 재협상합니다. 다른 KEX/Cipher나 사용자
공개키 서명 정책은 약화하지 않습니다. 최종 로그인 전 SHA-256 호스트키
지문 검증·최초 신뢰 승인은 기존과 동일하며 PoE 구성 명령은 재시도하지 않습니다.

가능하면 장비의 ArubaOS-Switch 버전과 `show ip ssh` 결과를 확인하여 더 강한 알고리즘을 활성화하는 것이 좋습니다.

Paramiko 4.0.0의 RSA/SHA-1 허용과 관련된 현재 예외, 배포 버전별 적용 범위와
제거 조건은 [의존성 감사 예외](DEPENDENCY_AUDIT_EXCEPTIONS_KO.md)에 기록되어
있습니다.

## 취소 동작

사용자가 취소하면:

- 새 장비 작업을 추가 배정하지 않음
- 열린 SSH 세션 종료 시도
- 이미 정상 완료된 백업은 보존
- 미완성 파일은 정상 결과로 취급하지 않음

## 단일 포트 제어의 별도 경계

`PortControlSSHSession`은 백업 세션과 별도 인스턴스입니다. 승인된 지문과 2930F
모델, 실제 포트 행을 확인한 뒤 대상 확인 문자열과 조회한 설정을 재검증합니다.
허용된 PoE OFF/ON, 포트 disable/enable 외 임의 명령은 실행할 수 없습니다.
변경 명령은 한 번만 전송하고 결과를 다시 조회합니다. 설정 저장, 자동 전원 재시작,
여러 포트 제어와 변경 명령 재시도는 제공하지 않습니다.

백업 진단 로그에는 기존 비민감정보 정책을 유지합니다. 별도 포트 작업 이력은
대상 식별을 위해 장비 IP·호스트명을 포함하지만 암호나 장비 설정 원문은 포함하지 않습니다.

## 현장 투입 전 권장 확인

포트 제어의 사용자 흐름은 [PORT_CONTROL_KO.md](PORT_CONTROL_KO.md)를 참고하십시오.

1. 소수 테스트 장비에서 먼저 실행
2. 수동 `show running-config`와 백업 TXT 비교
3. 장비명과 모델/SKU가 정상 식별되는지 확인
4. `result.xlsx`의 성공/실패 집계 확인
5. SSH 장비 지문 검토 절차를 운영팀과 합의
6. 동시 접속 수를 낮게 시작한 뒤 수집 시간을 보고 확대
7. 백업 파일 보관 위치의 접근 권한 확인

실제 장비 검증 결과가 없는 상태에서 자동 테스트만으로 운영망 전체에 즉시 확대하는 것은 권장하지 않습니다.


## v0.8.1 개발: 백업 저장 권한 점검 (B안)

- 새 실행 폴더 및 TXT 파일은 POSIX에서 각각 소유자 전용 `0700` / `0600`으로 저장합니다.
- Windows 11에서는 `chmod`를 NTFS ACL 제어로 오인하지 않습니다. 실행 폴더에 대해 `icacls`를 **읽기 전용으로** 호출해 광범위한 사용자 그룹에 읽기/쓰기 권한이 보이면 결과 경고로 남깁니다.
- 도구 실행 불가·ACL 해석 불가도 권한이 안전하다고 판단하지 않으며 직접 권한 검토를 안내합니다. 자동 점검은 상속·그룹·공유 권한 전체를 증명하지 않습니다.
- 공유 경로를 사용자가 명시적으로 선택했다면 프로그램은 위치를 임의 변경하거나 사내 ACL을 수정하지 않습니다. 경고는 백업 수집·진단 로그 기록을 막지 않으며 Excel 결과와 GUI에 남습니다.
- 민감한 `running-config`의 공유 또는 외부 업로드 전에는 운영자가 NTFS 공유/상속 권한과 비밀정보 포함 여부를 직접 확인해야 합니다.

## v0.8.1 개발: 일괄 AP 포트 차단 직전 확인

- 최초 조회가 AP-535 단일 LLDP 이웃이고 Chassis ID·상대 Port ID가 있어야 일괄 PoE OFF/포트 Down 대상으로 승인됩니다.
- 변경 직전에 스위치 IP·SSH 지문·호스트명·포트 설정뿐 아니라 **변경 명령을 전송할 동일 SSH 세션에서** LLDP 이웃 모델, Chassis ID, 상대 Port ID를 다시 확인합니다.
- 이웃 없음·다중 이웃·케이블 변경·LLDP 실패는 모두 차단합니다. 성공·오류의 명령 전송은 자동 재시도하지 않습니다. 단일 포트 제어와 PoE ON의 기존 조작 흐름은 유지합니다.


## 2026-11-18 B안 2차: LLDP 캐시/명령 전송 분류

- 일괄 PoE OFF/포트 Down은 처음 조회한 AP-535 LLDP Chassis ID·Remote Port ID뿐 아니라 **조회 당시 및 실제 변경 직전 Link Up**을 요구합니다. Link Down에서 과거 이웃 정보만 남은 상황은 변경 대상에서 제외합니다.
- 실제 변경 명령 직전에는 동일 SSH 세션에서 링크/구성 상태와 LLDP 식별자를 다시 확인합니다. LLDP 이웃 없음·변경·조회 오류는 전송 전 실패로 처리합니다.
- **한계:** Link Up과 Chassis ID가 일치해도 수신된 LLDP TLV의 최신성까지 증명되는 것은 아닙니다. 케이블 재패치·재연결 직후 또는 LLDP 광고가 불안정한 포트는 운영자가 별도 확인해야 합니다. 이 검증을 "실시간 AP 식별 보증"이라고 해석하지 마십시오.
- `PreMutationRejected`는 포트 구성 변경 명령을 아직 전송하지 않았음을 확인할 수 있는 경로에서만 생성합니다. 배치의 사전 `intent` 뒤에 이 오류가 발생하면 `preflight_failed` 결과를 기록하고 이후 대상 작업을 진행할 수 있습니다.
- 실제 변경이 시작된 이후의 통신/응답 오류는 기존 `unverified`로 중단하고 재전송하지 않습니다. 프로세스 비정상 종료로 `intent`만 남은 경우도 `result_unknown` 유지입니다.
- 단일 포트 직접 제어와 PoE ON의 기존 절차는 유지하며, 자동 복구·자동 재시도·`write memory`는 수행하지 않습니다.


## WC.16.01 서버키 자동 호환 연결 (v0.9.5)

기본 알고리즘 협상부터 시도합니다. `no acceptable host key` 오류로 서버 호스트키에서만 실패했다면 새 사전 SSH 탐색 연결을 최대 1회 생성해 `ssh-rsa` 서버 서명 방식으로 재협상하고, 성공 시 해당 IP:SSH포트만 현재 실행 동안 호환 모드로 기록합니다. 인증 정보 전송은 등록된 SHA-256 서버 지문이 검증된 이후에만 허용하며 처음 보는 서버키는 기존 신뢰 승인 절차를 거칩니다. 수동 호환 버튼은 없으며 PoE 조회 결과에 `레거시 SSH`라고 표시합니다. 중간자에 의한 알고리즘 강등과 SHA-1 서명 위험이 남으므로 펌웨어 업그레이드를 권장합니다. [상세 절차](SSH_LEGACY_COMPAT_KO.md).
