# Aruba 2930F · 실행 세션 SSH 계정 통합 (A안)

> v0.8.0 개발 브랜치 적용 사항. 사용자 승인 전 `main` 병합 및 공식 릴리스 발행 금지.

## 사용자 이용 순서

1. 프로그램 실행 → 메인 화면 상단 **SSH 계정 설정…** 클릭. 프로그램을 먼저 탐색하더라도 최초 SSH 작업 버튼을 누를 때 미설정 계정 입력창이 자동 표시됩니다.
2. 사용자 이름, SSH 비밀번호, 필요한 경우 Enable 암호 입력 → **현재 실행에 적용**.
3. 컨피그 백업, 포트 조회, PoE OFF/ON, 고급 단일 포트 제어를 전환하며 재입력 없이 사용.
4. 동일 실행 중 계정 전환이 필요하면 **계정 변경…**, 중단하려면 **세션 해제** 클릭.
5. 프로그램 종료 시 해당 세션의 인증 정보 참조를 정리합니다. 프로그램을 다시 열면 재입력해야 합니다.

모든 스위치에 하나의 계정을 사용하는 단순 모델입니다. 서로 다른 인증 계정이 필요한 장비에 대한 개별 계정 맵, 자동 계정 전환, 운영체제 자격 증명 보관소/DPAPI 저장은 이번 범위에 포함하지 않습니다.

## 설계와 보안 경계

- `SessionCredentialStore`는 현재 프로세스의 메모리에서만 `Credentials`를 보유합니다.
- 통합 메인 창만 이 객체를 소유하며 백업/포트 조회/제어 Worker는 작업 시작 때 검증된 세션의 불변 자격 증명을 전달받습니다.
- 백업 종료 시 기존 개별 비밀번호 입력란을 지워도 메인 세션은 사라지지 않습니다. 기존 독립 실행 GUI에서는 원래의 보안 정책과 입력/초기화 동작이 유지됩니다.
- 사용자가 계정을 바꾸거나 세션을 해제하면 기존 포트 조회 캐시와 체크 선택·제어 계획을 무효화합니다. 재조회 전 해당 상태를 기준으로 전원 변경할 수 없습니다.
- SSH 작업 진행 중 계정 변경·세션 해제를 거부합니다.
- Username은 상단에 표시하지만 비밀번호와 Enable 암호는 표시·CSV/HTML/JSONL 기록·프로필/설정 파일 저장하지 않습니다.
- 다만 Python 불변 문자열의 물리적 메모리 완전 영구 삭제(제로화)는 보장하지 않습니다. 종료/해제 시 참조 제거를 수행합니다.
- 호스트 키 지문 승인, 실제 장비 SSH 인증·Enable 권한, 명령 전 대상 재검증, AP-535 보호 및 결과 불확실 시 자동 재시도 금지는 변경하지 않습니다.

## 자동 검증

- SessionCredentialStore 미설정/설정/교체/해제, `Credentials` secret repr 억제
- 실제 PySide6 계정 설정창의 암호 마스킹, OK 입력 검증, 취소/종료 후 UI 암호 삭제
- 프로그램에서 백업 요청과 포트 조회가 같은 세션 Credential 객체를 사용하는지 확인
- 백업 종료 후에도 공통 세션 재사용, 이전 입력란 비어 있음
- 계정 변경·해제 시 이전 포트 조회/작업 선택 초기화, 실행 중 변경 차단
- 고급 단일 제어는 Provider를 직접 받아 독립 GUI 대비 추가 비밀번호 사본을 입력창에 만들지 않음
- 독립 실행 백업/포트 GUI 구 방식 및 Windows 포터블 빌드, Ruff/mypy, 기존 회귀 테스트 유지
- 실제 운영 Aruba 2930F 인증·권한/PoE 제어 검증은 사용자가 현장에서 수행

**확인:** 공통 계정은 네트워크 장비의 권한을 우회하지 않습니다. 스위치가 해당 계정을 거부하면 해당 장비의 로그인 실패로 표시합니다.
